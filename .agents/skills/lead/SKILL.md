# Lead
1. **Loop.** Take the next roadmap items. Start one worker per item in its own worktree through Orca (the `orchestration` skill). Codex, Claude Opus and DeepSeek Harness build (code and research); a model family other than the builder's reviews. On every worker report keep going: decide by the recommended option, ask the owner only for a boundary.
2. **Worker task rules.** The boundaries of `AGENTS.md` (name only what is forbidden), then "Everything else is allowed without asking". Always add: this machine is shared, so stop only a process you started, by its PID; never by name (`pkill`, `killall`, `kill` on a `pgrep` pattern).
3. **Codex routing.** Build and review on the default (`gpt-6-astra`, high); bulk: `worker-start --agent codex --model gpt-6.1-sol --effort medium`. Plain spec for a plain task, `$ralplan` for a design-heavy one, `$ultragoal` for a long multi-part one. Reports include the done command's output.
   - Before each Codex dispatch run `uv run python .agents/skills/lead/scripts/trigger_words.py DISPATCH.txt`: it prints the installed oh-my-codex detector's matches without a model call. Reword or quote unintended triggers, including "code review", "review code", "plan the", "plan this", "investigate", "consensus plan", "gather requirements", "don't assume"; absent package is a failed precheck.
4. **Land one branch at a time**, from the main checkout (`G="uv run python .agents/skills/lead/scripts/gate.py"`). At dispatch, `$G register BRANCH --builder codex|claude --task TASK_ID`: Orca's task listing has neither branch nor builder. `$G pending [--run RUN_ID]` is the hourly automation's precheck (0 only for a completed registered task with an unmerged branch); the lead creates the automation.
   - On worker completion run `$G auto BRANCH --builder codex|claude "TITLE" BODY.md` in the background, through an Orca terminal so its exit wakes the lead. It runs trial, the other family's headless review, open and land; the first failure prints the reply to send to the worker.
   - By hand: `$G trial BRANCH`, `$G review BRANCH --builder codex|claude`, `$G open BRANCH "TITLE" BODY.md [REVIEW.json]`, `$G land BRANCH [SQUASH.txt]`. Trial merges main and checks the branch; open validates the review's tested commit and family before pushing. Findings must be `fixed` or `closed: reason`; unknown prose stays unresolved. Fixed code needs a new trial and review.
   - A local holder retains `~/.cache/meridian/landing.lock` with flock between commands; `auto` also holds one connection throughout. A failed/interrupted command keeps the reservation for retry; `$G release` explicitly abandons it. Land pins the tested head, requires green CI and equal merged/tested trees, then compares main again. If main moves during the merge, run checks on main.
5. **After each merge**: update the roadmap and the manifest (the owner's files, outside the repository), then take the next item.
