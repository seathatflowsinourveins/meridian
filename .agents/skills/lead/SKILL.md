# Lead
1. **Loop.** Take the next roadmap items. Start one worker per item in its own worktree through Orca (the `orchestration` skill). Codex, Claude Opus and DeepSeek Harness build (code and research); a model family other than the builder's reviews. On every worker report keep going: decide by the recommended option, ask the owner only for a boundary.
2. **Worker task rules.** The boundaries of `AGENTS.md` (name only what is forbidden), then "Everything else is allowed without asking". Always add: this machine is shared, so stop only a process you started, by its PID; never by name (`pkill`, `killall`, `kill` on a `pgrep` pattern).
3. **Codex routing.** Build and review on the default (`gpt-6-astra`, high); bulk: `worker-start --agent codex --model gpt-6.1-sol --effort medium`. Plain spec for a plain task, `$ralplan` for a design-heavy one, `$ultragoal` for a long multi-part one. Reports include the done command's output.
   - Before each Codex dispatch run `uv run python .agents/skills/lead/scripts/trigger_words.py DISPATCH.txt`: it prints the installed oh-my-codex detector's matches without a model call. Reword or quote unintended triggers, including "code review", "review code", "plan the", "plan this", "investigate", "consensus plan", "gather requirements", "don't assume"; absent package is a failed precheck.
4. **Land one branch at a time**, from the main checkout (`G="uv run python .agents/skills/lead/scripts/gate.py"`). At dispatch, `$G register BRANCH --builder codex|claude --task TASK_ID`: Orca's task listing has neither branch nor builder. `$G pending [--run RUN_ID]` is the hourly automation's precheck (exit 0: pending, 1: idle, 2: query/fetch failure); the lead creates the automation. Pending names waits for worker changes or lead dispositions; dead runs retry, transient lead failures retry up to three times (`--retry-limit`), then need an explicit auto retry. It fetches only for a remaining candidate.
   - On worker completion run `$G auto BRANCH --builder codex|claude "TITLE" BODY.md` in the background, through an Orca terminal so its exit wakes the lead. It validates BODY before reserving, then runs trial, the other family's headless review, open and land; code/check failures print `SEND TO WORKER`; numbered review candidates and other failures print `LEAD ACTION`. The lead verifies candidates, sends confirmed defects to the worker, and closes false positives with `$G close BRANCH NUMBER "REASON" [--also NUMBER "REASON"]`; fix claims are refused. Re-run auto after closing all: it reuses the tested commit and review, while a new commit needs both again.
   - By hand: `$G trial BRANCH`, `$G review BRANCH --builder codex|claude`, `$G open BRANCH "TITLE" BODY.md [REVIEW.json]`, `$G land BRANCH [SQUASH.txt]`. Trial merges main and checks the branch; open validates the review's tested commit and family before pushing. The final record contains only the current round: no findings, or each `closed: reason`; `fixed` and closing reasons claiming a fix are refused. Fixed code needs a new trial and review, which replaces the old round.
   - A local holder retains `~/.cache/meridian/landing.lock` with flock between commands; `auto` also holds one connection throughout. Contending commands refuse immediately. Auto releases on every exit, including client disconnect; failed/interrupted hand-run commands keep the reservation for retry except reviewer/CI deadlines; `$G release` explicitly abandons it, cleaning dead-holder leftovers only under the shared flock. Land pins the tested head, requires green CI and equal merged/tested trees, then compares main again and marks the registration landed. If main moves during the merge, run checks on main.
   - Reviewer ceiling: `--review-timeout 900`; CI ceiling: `--ci-timeout 1800` (seconds); both return to the lead and release. Claude defaults to `--review-level medium` (`high` available), with a schema and read-only tools; Codex native bullets are candidates, other output is unclassified.
   - Upgrade: an old `meridian-gate/lock` refuses new landings and names its branch; finish or release with the old gate first.
     Old state names are not migrated: start a new trial; end any old shared-lock holder with its matching gate version before switching protocols.
5. **After each merge**: update the roadmap and the manifest (the owner's files, outside the repository), then take the next item.
