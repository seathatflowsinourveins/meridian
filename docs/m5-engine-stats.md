# Engine analysis at 2.0.0rc9 (M5 groundwork)

Read 2026-11-13: installed Python files match tag commit `da6b57aefdd62b44f675e434ffcfefca7f4025dd` byte for byte. Compiled internals were read at that commit, not inferred from older APIs. Start from upstream's [synthetic backtest example](https://github.com/nautechsystems/nautilus_trader/blob/da6b57aefdd62b44f675e434ffcfefca7f4025dd/examples/backtest/synthetic_data_pnl_test.py#L249-L261): run, generate reports, then dispose.

The [analyzer's default registry](https://github.com/nautechsystems/nautilus_trader/blob/da6b57aefdd62b44f675e434ffcfefca7f4025dd/crates/analysis/src/analyzer.rs#L75-L100) supplies these statistics (names below are classes):

| Input | Registered by default |
|---|---|
| Realized PnLs | MaxWinner, AvgWinner, MinWinner, MinLoser, AvgLoser, MaxLoser, Expectancy, WinRate |
| Returns | ReturnsVolatility, ReturnsSkewness, ReturnsKurtosis, ReturnsAverage, ReturnsAverageLoss, ReturnsAverageWin, SharpeRatio, SortinoRatio, TailRatio, ProfitFactor, RiskReturnRatio |
| Positions | LongRatio |

The analyzer also supplies `PnL (total)` and `PnL% (total)`. The [rc9 statistic modules](https://github.com/nautechsystems/nautilus_trader/blob/da6b57aefdd62b44f675e434ffcfefca7f4025dd/crates/analysis/src/statistics/mod.rs) additionally ship CAGR, CalmarRatio, ExpectedShortfall, MaxDrawdown, OmegaRatio, UlcerIndex and ValueAtRisk, plus benchmark statistics Alpha, BetaRatio, DownCaptureRatio, InformationRatio, TrackingError, TreynorRatio and UpCaptureRatio. These are not in the default registry; this report adds none. [PortfolioStatistic](https://github.com/nautechsystems/nautilus_trader/blob/da6b57aefdd62b44f675e434ffcfefca7f4025dd/python/nautilus_trader/analysis/statistic.py) supports custom returns, realized-PnL, position and benchmark calculations; none is needed here.

The portfolio's [Rust analyzer](https://github.com/nautechsystems/nautilus_trader/blob/da6b57aefdd62b44f675e434ffcfefca7f4025dd/crates/portfolio/src/portfolio.rs#L2240-L2288) aggregates accounts, cached positions and position snapshots, retaining close-time PnLs across netting re-entry. Python exposes `portfolio.statistics()`, not `portfolio.analyzer`; [engine.get_result()](https://github.com/nautechsystems/nautilus_trader/blob/da6b57aefdd62b44f675e434ffcfefca7f4025dd/crates/backtest/src/engine.rs#L1369-L1423) calls it and exposes `stats_pnls` (by currency), `stats_returns`, `stats_general`, `returns_series`, and position/order counts. `run_analysis=False` only suppresses [post-run logging](https://github.com/nautechsystems/nautilus_trader/blob/da6b57aefdd62b44f675e434ffcfefca7f4025dd/crates/backtest/src/engine.rs#L2386-L2390); statistics still work.

The engine's [ReportProvider](https://github.com/nautechsystems/nautilus_trader/blob/da6b57aefdd62b44f675e434ffcfefca7f4025dd/python/nautilus_trader/analysis/reporter.py) returns pandas DataFrames: orders indexed by client order ID; fills from individual OrderFilled events (quantity, price, side, timestamp); positions indexed by position ID with snapshots flagged. `generate_order_fills_report` instead summarizes filled orders; we use `generate_fills_report`. Empty reports have no columns. No DataFrame conversion or metric calculation is implemented here; CSV serialization retains engine columns and indices.

[create_tearsheet](https://github.com/nautechsystems/nautilus_trader/blob/da6b57aefdd62b44f675e434ffcfefca7f4025dd/python/nautilus_trader/analysis/tearsheet.py#L805-L926) takes a completed, undisposed engine (or BacktestResult, optionally its node). It reads result statistics and uses compatible mark-to-market portfolio snapshots for daily chart returns, falling back to account reports. It needs pandas and Plotly; no bars, benchmark, Kaleido or server is needed for the default HTML. Defaults show run information, statistics, equity, drawdown, monthly returns, distribution, rolling Sharpe and yearly returns. rc9 calls `Figure.write_html` with [Plotly's default `include_plotlyjs=True`](https://github.com/plotly/plotly.py/blob/v7.1.0/plotly/io/_html.py#L346-L405): the script is embedded in the single file, with no CDN dependency.

There is no development-only feature in that compared surface; all APIs used here are verified at rc9. No claim is made about unrelated development changes.

Run `uv run --group research python -m meridian.strategy_template.sim --report` (optionally `--copies N`). It prints the engine's statistics and creates `runs/M5-template-<uuid>/{statistics.json,orders.csv,fills.csv,positions.csv,tearsheet.html}` beside the existing simulation record. Without the group, `--report` names the missing dependency and exits 2 before simulation; ordinary simulation still works. Meridian imports only the engine and standard library; the engine imports pandas/Plotly. The research group is optional, and CI explicitly exercises it.

Interpretation: this is a seconds-long synthetic fixture, not evidence of performance. In rc9's [snapshot/PnL implementation](https://github.com/nautechsystems/nautilus_trader/blob/da6b57aefdd62b44f675e434ffcfefca7f4025dd/crates/analysis/src/analyzer.rs), total PnL is the balance difference with no unrealized-PnL argument. For this cash venue, open purchases therefore remain cash outflows; it is not the mark-to-market equity chart change. [WinRate](https://github.com/nautechsystems/nautilus_trader/blob/da6b57aefdd62b44f675e434ffcfefca7f4025dd/crates/analysis/src/statistics/win_rate.rs#L65-L76) counts zero realized-PnL open positions in its denominator. We preserve those engine semantics, including netting snapshots, rather than replace them with custom metrics. Undefined/non-finite values become JSON null; the one-day fixture cannot support annualized risk claims.

`tests/test_strategy_report.py` recomputes cash change, position lifecycles and win rate from synthetic fills for closed-only and open/re-entry cases; checks CSV columns, snapshot history, no-trade and missing-group cases; generates the full command with Linux socket syscalls blocked; and parses HTML to require embedded Plotly, all eight sections and no external resource tags. M5 evaluation (purged cross-validation and deflated Sharpe), calibration and lane integration remain out of scope.
