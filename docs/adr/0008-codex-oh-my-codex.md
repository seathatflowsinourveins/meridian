# ADR 0008: oh-my-codex for Codex CLI (plan 8.6)

**Status: not adopted.** Decided 2026-11-13 by the pre-registered rule, applied to a real task done 3 times with and 3 times without it (R1): both arms passed 3 of 3, and the arm with oh-my-codex (OMX) used 104.4 % more tokens, where the rule asks for 25 % fewer. Measured in project scope, not in the default user scope (see Method). Nothing was installed for the owner. Data: the [pre-registration](data/0008-prereg.txt), the [arm key](data/0008-key.txt), the [R1 brief](data/0008-brief-R1.txt), the [results](data/0008-results.json), rebuilt byte for byte from the run folders by [this script](data/0008_aggregate.py), and the [M2 split](data/0008-m2.json). Sources, cited as (A), (V) and (M): the assessment (2026-11-12); an independent verification (2026-11-13: 44 checks, 39 confirmed, 5 corrected, 0 refuted; its corrected facts are used, and its fact sheet is the pre-registration); the measurement, run 1 (02:06 ET, M2) and run 2 (04:09 to 04:37 ET, M1 and R1). Their raw runs hold local paths and account fields and stay on the owner's machine.

## Need

Codex 0.167.2 here already has, built in and on: `/goal` (feature `goals`, stable; the handbook's Goals section), native subagents (`multi_agent`), hooks, skills and `AGENTS.md`; Orca 1.4.257 gives worktrees, task orchestration and status; `/codex:review` (openai/codex-plugin-cc 1.0.6) reviews from Claude Code. OMX is a workflow layer over Codex: an always-on instruction file, 24 skills (plan, ralplan, autopilot, ultragoal, performance-goal, team, code-review and others), 18 agent roles and 8 lifecycle hooks (A, V). Overlap, as fact: its ultragoal and performance-goal skills drive Codex's own goal tools (`create_goal`, `get_goal`, `update_goal`), a second layer over `/goal`; its roles run on Codex's native subagents; its team mode does part of what Orca's worktrees and orchestration do; its code-review skill reviews as `/codex:review` does; its plan and ralplan skills plan, as Claude Code's plan mode does in another runtime (V). Upstream publishes no comparison of Codex with and without OMX, and its README (L134) says users who want plain Codex probably do not need it (V).

## What it installs, writes and sends

Read in the source at the pin (A, V); `setup()` read in full and the hook dispatcher's import closure (158 files) scanned before anything ran (M). Setup defaults: user scope, install mode legacy, MCP none.
- A global npm CLI `omx`; its postinstall fetches an `omx-runtime` archive from the GitHub release (sha256-checked) into `~/.cache/oh-my-codex/native`.
- `omx setup` (user scope) writes `$CODEX_HOME/config.toml` (`developer_instructions`, which replace existing ones; `notify` running node after every turn; `[hooks.state]` trust entries for its own 8 hooks), merges its hooks into `hooks.json` beside Orca's, and writes `AGENTS.md` (26,674 bytes), 18 agents, 32 prompts, 24 skills and `$CODEX_HOME/.omx/`; it runs `gh auth status` (A, V, M).
- Hooks: 8 events, each starting node on a 1,047,778-byte dispatcher (V). In every repository Codex runs in, they write `.omx/` and, where it is not ignored, append `.omx/` to `info/exclude` (from a worktree, the main checkout's). The Stop hook continues a turn whose last 800 characters hold one of 10 stall phrases ("continue with", "keep going" and others), also when that message asks permission, telling the agent to go on "only if it is already authorized"; a permission question without a stall phrase does not trigger it (`auto-nudge.ts` L329-340, L433-440, L532-552 at the pin; A, V). Codex runs a user hook only when its stored hash is trusted; OMX's self-written trust made its SessionStart hook run in one probe whose rollouts were not kept, and is inferred, not shown, for the other 7 (M).
- Network: no telemetry host and no fetch on the hook path (V, M). Opt-in senders: notifications to discord.com, api.telegram.org or hooks.slack.com when configured, and api.layofflabs.com from its eval collector, off the setup and hook path (V). Through the `omx` launcher, which Orca does not use: an npm update check every 12 h, a one-time star prompt whose empty answer runs `gh api -X PUT /user/starred/Yeachan-Heo/oh-my-codex`, and `--hotswap`, which rotates auth slots on 429 or quota errors (A, V).
- No order tool or broker connector: its plugin declares no apps, and its 6 MCP servers (state, memory, code-intel, trace, wiki, hermes) are all `enabled: false` (read at the pin). Project scope writes the same into the repository's `.codex/`, `AGENTS.md` and `.gitignore` (V, M).

## Method

- Fixed before the runs: the [pre-registration](data/0008-prereg.txt) (sha256 `8aa7e7fd8b3e9d31eb505727691fd4e646a4794364051ffee5ea103526da4e5f`), the verification's fact sheet verbatim, whose last protocol bullet is the rule. The fact sheet's file was last written 2026-11-13 01:51:57 ET; run 1 began at 02:06 ET and run 2's first M1 run at 04:13:40. These are file times on the owner's machine and cannot be proved from the repository.
- Rule: adopt only if b passes more R1 runs (2 of 3 against at most 1, after any extension), or both pass every run and b uses at least 25 % fewer total tokens; and containment passes, no `tests/` edit, no auto-nudge continuation, no write outside the run's worktree.
- Planned: arms a = Codex 0.167.2, b = the same plus OMX set up in user scope, each in a throwaway `CODEX_HOME` the owner signs in; M1 (3 runs per arm of `codex exec ... 'Reply with exactly the word OK. ...'`); R1, the replay of `5d51c9c` at base `27aa964`, the brief verbatim, order a1 b1 b2 a2 a3 b3, 2 more per arm on a one-success gap or a 2-2 tie; graded by `ruff check`, `ruff format --check`, `pyright` and `pytest` (281 passed) on a fresh clone, `tests/` unchanged.
- Changed from the fact sheet before run 2's measurements, the rule unchanged (the pre-registration lists each with its time): the throwaway homes were not signed in and no agent copies a sign-in, so both arms ran in the owner's signed-in `~/.codex` and b in project scope (`omx setup --scope project --install-mode legacy --mcp none --merge-agents` in each b clone); both arms added `--dangerously-bypass-hook-trust`, a run-only trust flag and Orca's hooks off for the run; M1 ran a1 a2 a3 b1 b2 b3. Changes 1 to 5 and 7 were fixed before the first M1 run, 6 and 8 (b's grade, the void scan) before the first R1 run (04:17:40). Read after the results were seen: M1's validity (above), containment's narrower test and the idle-time reading (Results).
- Scripts, records of what ran, not rerun harnesses: [common](data/0008_common2.sh), [M1](data/0008_m1.sh), [R1](data/0008_r1.sh), [route proof](data/0008_proof.sh), [run summary](data/0008_codex_ab_summary.py), [void scan](data/0008_scan_run.py), [trust count](data/0008_trust_keys.py), [Gateway guard](data/0008_gateway_guard.sh). Before every run a guard checked that nothing listened on the paper Gateway's port and that no Gateway process ran. The first run's guard matched command lines and stopped this series falsely at 02:07 ET, before run 1's first M1 run; run 2 used the fixed guard, which printed `gateway down` before each of its 12 runs.

## Results (run 2, 2026-11-13; [results](data/0008-results.json))

- R1: all 6 runs exited 0 and passed the grade (pytest 281 passed, 72 failed before), `tests/` unchanged. Passes: 3 of 3 without, 3 of 3 with, so no extension. Voids: none (a void run is one whose result is not counted for its arm because a stated rule was broken; a void in the arm with the addition counts against it); the void scan's flagged inputs were reads, working-tree diffs, patch text or one offline test run, each reviewed, none of git history, the main checkout or another run.
- Tokens, sub-agents included: without 530,527, 472,677 and 638,632 (sum 1,641,836, median 530,527); with 1,028,944, 1,564,794 and 761,480 (sum 3,355,218, median 1,028,944): **+104.4 %** by sum, +93.9 % by median. Every b run spawned one OMX `executor` sub-agent (308,350, 684,396 and 265,078 tokens), no a run any. Model requests 12, 11 and 14 without; 19, 26 and 16 with.
- Wall time: median 208 s without (147, 208, 216), 139 s with (139, 162, 105). Every run asked once whether "connect to nothing" allowed the fake-Gateway tests and got no answer; a-2 and a-3 then idled in `sleep` 60 s and 30 s. Read after the results: without that idle time, 147, 148 and 186 s (median 148 s), so at n = 3 OMX is not shown to be faster.
- Hooks: OMX's SessionStart text appeared once in every b root thread. Stop auto-nudge, PostToolUse block and prompt triage texts: 0 in every run; the b runs ended asking the owner's word on those tests, with no stall phrase, and were not continued. Whether the other hooks ran was not observed.
- Containment failed the pre-registered test: with both arms in the owner's `~/.codex`, every run wrote its rollouts and Codex's state databases there, and at 04:26:32, when b-2 ended, the owner's `goals_1`, `memories_1` and `queue_1.sqlite` grew from 4,096 bytes to 32,768, 45,056 and 40,960 (the results' `owner_home`). On a narrower test defined after that failure it passed in every run: `config.toml` and `hooks.json` kept their sha256 and their 4 trust entries, no OMX path appeared in the home folder, no OMX process was left. The decision is the same on either test.
- Not measured: user scope in tokens and on R1; plugin mode and `--mcp compat`, which `/etc/codex/requirements.toml` keeps from running; `omx-runtime`, skipped by `--ignore-scripts`. Cost: 5,117,627 Codex tokens (M1 120,573; R1 4,997,054); no other runtime, no GitHub API call.

## Decision

Not adopted, by the pre-registered rule: both arms passed R1 3 of 3, and the arm with OMX used 104.4 % more total tokens, not 25 % fewer; it handed part of each run to a sub-agent and was not shown to be faster. Its always-on text added 7,611 to 8,075 tokens to a fresh session's first request (M1). The run was in project scope, without its `notify` and with its hooks run by the bypass flag; the rule's result in user scope is unknown. Also weighed, as facts: its always-on `AGENTS.md` opens with "EXECUTE TASKS TO COMPLETION WITHOUT ASKING FOR PERMISSION"; its Stop hook continues a turn ending in a stall phrase even when it asks permission; in user scope its self-written hook trust would let its hooks run beside Orca's without the owner's `/hooks` review (inferred from one hook); its launcher's `--hotswap` rotates auth slots, and its star prompt stars the repository from the account `gh` is signed in to; 184 versions in nine months.
