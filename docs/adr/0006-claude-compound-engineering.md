## Need

What it offers Claude Code workers: a plan, work, review, debug and "compound" (capture what was learned) loop as skills. Components here for those jobs: plan mode; `/goal`, which makes a runtime keep taking turns until a stated end state holds, where the owner's goals name a command whose exit code decides and no runtime runs a check of its own (`docs/HANDBOOK.md`, "Goals", on `m2/handbook-size-budget`); subagents, `/batch` and `/loop`; `/code-review`, `/security-review` and `/simplify`; the cross-family `/codex:review` from `openai/codex-plugin-cc` 1.0.6, which `AGENTS.md` requires before a merge; auto memory; Orca's worktrees and orchestration; and the rules in `AGENTS.md`.

## Method

- Fixed before the runs: [0006-prereg.txt](data/0006-prereg.txt) (sha256 `d9e31b9d79643c68f6d1f138c0c66f07b5d2e9d0227608ff2989546130ecff3b`), assembled on 2026-11-13 after the series, quotes each record with its time and hash. Before the first agent run (s2-a-k1, 04:10:52 ET): the key (01:59), the brief file, plans, deny rules and leak patterns (02:01), the rule as the first attempt's notes state it (02:04), the guard (02:41), the rule and brief in this ADR's draft (03:30, a local commit that was not published) and the runner `ab2.sh` (04:10:01). These times come from the owner's machine and cannot be proved from the repository. Changed after a run: `ab3.sh` (04:15:12), after R1's first attempt failed to start, changed only how `env` received the same variables, the void test and the folder prefix, before the first counted R1 run (04:15:22).
- Both arms: measured on Claude Code 2.1.322 with `claude-opus-5-5`; the stack's lead model `claude-fable-5-2` was not measured. Effort high, bypass permissions, a fresh auto-memory folder per run; 10 deny rules (`ibgateway`, `git push`, `gh pr`, `gh api`, `gh issue`, `acpx`, `npx`, session-history scripts, `curl`, `wget`) in a per-run `--settings` file and the method's other 5 in `--disallowedTools`, a departure from the method as the series used it. R1 also drops `GH_TOKEN` and `GITHUB_TOKEN`, points `CODEX_HOME` and `GH_CONFIG_DIR` at empty folders, sets `CROSS_MODEL_PEERS=none` (read by three of CE's four cross-model scripts, not by ce-work's) and a push URL that leads nowhere. Before every run a guard checked that nothing listened on the paper Gateway's port and that no Gateway process ran. The first attempt's guard matched command lines and stopped this series falsely at 02:02 ET, before any agent started; the published guard matches process names and executables. The runs used the owner's sign-in and wrote worktree entries under the main checkout's `.git/worktrees`; a session-only plugin load left a `pluginUsage` entry in `~/.claude.json`.
- The addition: an unauthenticated checkout of `d8f8e03` loaded with `--plugin-dir`; `plugin validate --strict` exits 1 on its one warning (a `CLAUDE.md` at the plugin root is not loaded), `plugin details` shows 38 skills and no agents, hooks, MCP or LSP servers. Always-on: `-p 'Reply with the single word OK. Do not use any tools.' --max-turns 1`, 3 runs per arm, interleaved a1 b1 b2 a2 a3 b3 (the key kept outside the run folders), `/context` after each.
- Task R1, the replay of the safety fix `5d51c9c`: a fresh detached worktree at `27aa964` with the tests of `5d51c9c`, given the [brief](data/0006-brief-R1.txt) verbatim in both arms (sha256 `78979180…a4feabc4`); 3 runs per arm in the same order, `--max-turns 100`. The arm with CE did not prefix `/compound-engineering:ce-debug`, as the assessment's protocol did: the series measures the plugin loaded and left to the model. Grade: the run's diff from `27aa964` to `meridian/` and `.gitignore`, applied to a fresh worktree, must pass `uv run ruff check . && uv run ruff format --check . && uv run pyright && uv run pytest`, with `tests/` equal to `5d51c9c` and nothing changed elsewhere. Checked first: unchanged, 72 tests fail; with `5d51c9c`'s fix, 281 pass.
- **Rule (the method's default plus a containment clause): adopt only if the with arm passes at least 2 of 3 and the without arm at most 1; or both pass at least 2 of 3 and the with arm uses at least 25% fewer median tokens (sum over `modelUsage`); the always-on delta at most 2,000 tokens unless the first condition holds; no containment violation (such a run is void and counts against the addition).** A one-success gap or a 2-2 tie adds 2 runs per arm. A void run is one whose result is not counted for its arm because a stated rule was broken; a void in the arm with the addition counts against it.

## Decision

Not adopted. The first condition fails (the arm without also passed 3 of 3); the second fails (CE used 0.6% more median tokens, not 25% fewer); the always-on delta, +2,866 tokens, is over the 2,000 cap. Under the verbatim brief the model never invoked it, so here it only adds its listing to every request. The static evidence agrees: upstream's only with/without, at commits before the pin, puts `lfg` at about 8.5 to 55 times the cost of plain Claude Code with no difference on the one graded outcome. Overlap, as fact: plan (plan mode), work (`/goal`, subagents, Orca), review (`/code-review`, `/simplify`, `/codex:review`), debug (Claude Code itself passed R1 3 of 3 without it; `/codex:rescue` hands a diagnosis to Codex) and capture (auto memory). Its defaults conflict with this stack's rules: run-time `npx` of range-resolved packages that send diffs to another provider, branches and local commits made without asking, tests and `docs/solutions/` written without asking into a public repository, and reads of other runtimes' session transcripts. Nothing changes: no configuration, no allowlist. Not decided here: the same commit's Codex plugin (`.codex-plugin`) and Antigravity package (`.agy`); `/etc/codex/requirements.toml` pins Codex plugins off, and `setup.sh agents-check` fails once `~/.gemini/config/plugins` exists (L600 at `9c5daaa`).
