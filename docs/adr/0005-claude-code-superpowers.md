# ADR 0005: obra/superpowers for Claude Code (plan 8.6)

**Status: not adopted**, decided 2026-11-13. This ADR covers 3 additions from one source, as plan 8.6's candidate list names it (`obra/superpowers`), and decides each separately: the Claude Code plugin, by measurement, and the same commit's Codex and Antigravity (agy) manifests, for which no with/without task was run (Decision). Data and scripts: the [pre-registration](data/0005-prereg.txt), the [arm key](data/0005-key.txt), the [brief](data/0005-brief-R1.txt), the [runner](data/0005_ab.sh) with its [deny rules](data/0005-deny.json), [leak patterns](data/0005-leak-patterns.txt) and [progress check](data/0005_status.sh), and the [results](data/0005-results.json), from which the [aggregator](data/0005_aggregate.py) recomputes the medians. The sheets [ab-claude-code.md](data/ab-claude-code.md) and [ab-tasks.md](data/ab-tasks.md) describe the shared method. The assessment, verification and measurement notes and the raw runs hold local paths and are not published.

## Need

A shared working method for Claude Code workers (brainstorm, plan, test first, debug, review), shipped as a plugin. Components here that do parts of that job: Claude Code's plan mode; subagents, `/batch` and the bundled `/code-review`; `/goal`, which makes a runtime keep taking turns until a stated end state holds, where the owner's goals name a command whose exit code decides and no runtime runs a check of its own (`docs/HANDBOOK.md`, "Goals", on `m2/handbook-size-budget`); the cross-family `/codex:review`; Orca's worktrees and orchestration; and the rules under "Working rules" in `AGENTS.md` to find the root cause and to run the checks before saying something works.

## What it installs, writes and sends

Read at the pin (manifest, hooks, every skill script) before any run; `claude plugin validate --strict` passed with an icon warning only.
- 15 skills (frontmatter name and description only) and one hook. No agents, commands, MCP or LSP servers, monitors, `bin/` or settings, and no dependency install. An install writes the plugin cache, `installed_plugins.json`, `known_marketplaces.json` and the marketplace clone under `~/.claude/plugins/`, and `enabledPlugins` and `extraKnownMarketplaces` in `~/.claude/settings.json`. Loaded with `--plugin-dir`, as here, it installs nothing; Claude Code itself wrote an empty `~/.claude/plugins/data/superpowers-inline` (removed after the series) and a `pluginUsage` entry `superpowers@inline` in `~/.claude.json`, whose `usageCount` read 9 on 2026-11-13 at 04:05 ET, as many as the series' sessions with the plugin (results, `plugin_usage_addendum`).
- The hook: `SessionStart`, matcher `startup|clear|compact`, `async` false. `hooks/session-start` reads `skills/using-superpowers/SKILL.md` with shell builtins and prints it, wrapped in `<EXTREMELY_IMPORTANT>`, as `additionalContext`. No network, no file write, no child process. That text orders a skill check before any reply on "even a 1% chance" and brainstorming before plan mode.
- When followed, the skills write `docs/superpowers/specs/` (committed) and `docs/superpowers/plans/`; `.superpowers/`; `~/.superpowers/diagnosing-superpowers/`; `.worktrees/` with a committed `.gitignore` edit; and `/tmp/review-<sha>` git worktrees. They run `poetry install`, `npm install` or `pip install`, graphviz, `npm test` loops, `gh search issues` and, after approval, `gh issue create --repo obra/superpowers`.
- Brainstorming's companion runs `node server.cjs` under `nohup` on 127.0.0.1, random port; its guide says to rebind to `0.0.0.0` when the page is unreachable, against the rule under "Agents and worktrees" in `AGENTS.md` that agents' servers bind 127.0.0.1. Its page loads a logo from primeradiant.com carrying the version unless `SUPERPOWERS_DISABLE_TELEMETRY`, `DISABLE_TELEMETRY` or `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` is set; the README calls this telemetry, and the stack sets none of the three.

## Always-on context

- Reconstructed from the pinned source: the bootstrap, 3,405 characters (791 tokens), at start and, by the hook's matcher, again after every `/clear` and compaction (not measured); the 15-line skill listing, 2,885 characters (561 tokens), on every request. These tokens are o200k_base, OpenAI's vocabulary, a proxy because Claude's tokenizer is not available offline. On invocation the 15 skill bodies hold 139,500 characters (32,520 tokens).
- Measured in Claude tokens (input plus cache tokens of a one-turn `OK` run, 3 runs per arm, each in a fresh worktree at `main` `9c5daaa`): without, 22,743 in all three; with, 24,919 in all three: **+2,176 (+9.57%)**, 1.61 times the o200k figure. Every with-run's hook printed 3,604 characters, and R1's first request carried the same +2,176 (21,882 → 24,058 in every run). `/context` understates it: its total rises 1,318 (16,444 → 17,762), with Messages +1,318 (the bootstrap), Skills 3,066 → 4,022 (+956) and System tools 7,473 → 6,517 (−956). For scale, `AGENTS.md` is 3,169 tokens in `/context`. Over the 14 median turns of R1 without it, the delta comes to about 30,464 tokens per R1-sized session.

## Method

- Fixed before the runs: [0005-prereg.txt](data/0005-prereg.txt) (sha256 `33b89bb02f4457d1d6bd6e7f96faf3a96eafe5598097ee4e5fd855c5b1e2e0c7`), assembled on 2026-11-13 after the series from records whose file times precede the first run (a-k1, 01:37:21 ET): the assessment's rule and vetoes (2026-11-12 21:31), the verification's fixes (22:34), the arm key (01:31), the deny rules, leak patterns and brief (01:34 to 01:35) and the runner (01:36). These times come from the owner's machine and cannot be proved from the repository; nothing was committed before the run. Settled after the runs: applying the method's 2,000-token cap (first in the measurement notes at 02:03 ET; the series ran 01:37 to 02:00), and recording as departures, in the pre-registration, choices the runner made the same in both arms where the assessment's protocol differed (the always-on base `9c5daaa`, not the fact sheet's `f65d835`; the method's model, brief, run order, token sum and always-on prompt; plugin-folder listings in place of hashes of the settings files).
- Both arms: measured on Claude Code 2.1.322 with `claude-opus-5-5`; the stack's lead model `claude-fable-5-2` was not measured. Effort high, bypass permissions, a fresh memory folder per run. All 10 deny rules in a per-run `--settings` file and the 9 without `ibgateway` also in `--disallowedTools`; that placement, 4 rules beyond the method's 6 (`poetry`, `npm install`, `gh issue`, `start-server.sh`) and `SUPERPOWERS_DISABLE_TELEMETRY=1` depart from the method as the series used it, set before the first run and the same in both arms. The arm with superpowers adds `--plugin-dir` on a checkout of `22f0b463`. Before every run a guard checked that nothing listened on the paper Gateway's port and that no Gateway process ran. The runs used the owner's sign-in and wrote worktree entries under the main checkout's `.git/worktrees`; a session-only plugin load left a `pluginUsage` entry in `~/.claude.json`.
- R1, the replay of safety fix `5d51c9c`: a fresh detached worktree at `27aa964` with `tests/` from `5d51c9c` and `uv sync --locked`; one brief (sha256 `78979180…a4feabc4`); order a-1 b-1 b-2 a-2 a-3 b-3, the arm letters drawn at random and kept outside the run folders until the series ended (the operator passed the arm flag; grading is by exit codes). Graded in another fresh worktree from the run's `meridian/` and `.gitignore` patch: `ruff check`, `ruff format --check`, `pyright` and `pytest` all exit 0, `tests/` equal to `5d51c9c`, nothing changed elsewhere. The grader was checked first: no change fails (72 failed), `5d51c9c`'s fix passes (281 passed).
- After every run: `git status --ignored`, `git worktree list`, refs, `~` and `/tmp`, `~/.superpowers`, `/tmp/brainstorm-*`, `/tmp/review-*`, plugin data, companion processes, and a leak scan of the stream, the transcript and subagents. Vetoes: any change under `tests/` or outside `meridian/` and `.gitignore`, a command that starts the IBKR lane, an install other than uv, a post to GitHub, a listener off loopback.
- **Rule (the assessment's): adopt only if no veto fires and either superpowers passes at least 2 of 3 where the arm without passes at most 1, or both pass 3 of 3 and superpowers uses at least 25% fewer median turns and total tokens.** A one-run miss allows 2 more runs per arm, once. A void run is one whose result is not counted for its arm because a stated rule was broken; a void in the arm with the addition counts against it.

The guard passed all 18 times it ran, each before an agent started; nothing was checked during or after a run. The [runner](data/0005_ab.sh)'s header gives both copies' hashes and the three lines changed for publication. Scope: one task, n=3, headless with a precise brief; interactive brainstorming and planning and the TDD and review skills were not tested.

## Decision

Not adopted: the Claude Code plugin. On the pre-registered rule the first condition fails (the arm without also passed 3 of 3) and the second fails (superpowers used 7.1% more median turns and 24.6% more median tokens, not 25% fewer); no veto fired. The always-on delta, 2,176 tokens, is also over the method's 2,000-token cap, applied after the runs (Method); the decision does not rest on it. The static evidence agrees: its maintainers' eval lab calls its run "not a Superpowers-versus-stock result"; its first Claude code-review pair, with Superpowers v6.3.0, passed in both arms at 13.9 times the cost and 6.3 times the time, and the lab says one pair cannot establish an effect. Its planning, review, subagent and worktree parts overlap plan mode, `/code-review`, subagents and Orca's worktrees (Need), and it conflicts with `uv sync --locked` (it runs `poetry install`), with review by a different model family (`AGENTS.md`, "Agents and worktrees"; its reviewer is a same-family subagent), with design documents committed into this public repository, and with `setup.sh agents-check`, whose `check_claude` allows no enabled plugin but `codex@openai-codex`. Nothing changes: no configuration, no allowlist.

Not adopted: the `.codex-plugin` and `.antigravity-plugin` (agy) manifests of the same commit, both at version 7.0.2 (read with `git` on 2026-11-13). No with/without task was run for them; they were decided on static grounds: the Codex requirements pin plugins off (`plugins = false` in `/etc/codex/requirements.toml`, a machine policy that `setup.sh agents-check` checks), `setup.sh agents-check` fails once `~/.gemini/config/plugins` exists (a check of this repository, not a machine policy), and the Claude Code plugin from the same commit showed no gain above.
