# ADR 0015: claude-hud status line for Claude Code (plan 8.6)
**Status: adopted.** Decided 2026-11-13 on the owner's instruction, not on a measurement.

**Need:** see context use, plan limits, running tools, subagents and todos while a session works. Claude Code has no status display of its own; its one `statusLine` command was held by Orca's reporter, which prints nothing and only posts usage figures to Orca.
**Candidate:** [jarrodwatts/claude-hud](https://github.com/jarrodwatts/claude-hud/tree/v0.15.0) **v0.15.0**, commit `b86e1c3e5255880578de4b7cc87dc383228c2a18` (2026-11-02), MIT, maintainer Jarrod Watts; read 2026-11-13: 29k stars, last push 2026-11-10. GitHub marks that commit verified. The head is not: 0.15.1 to 0.15.3 are untagged releases cut by `claude-hud-maintainer[bot]`, an unattended agent that turns issues and pull requests from anyone into merged patches (`maintainer/PLAYBOOK.md`). So the pin is the tag, and the marketplace does not follow upstream.
**Advisories:** [its advisories page](https://github.com/jarrodwatts/claude-hud/security/advisories), read 2026-11-13 through the API, lists four, all fixed at or before the pin: GHSA-25hg-g83m-4w35 and GHSA-f7gq-pcm8-rxr4 (high, a repository's git configuration ran commands on a render; fixed 0.15.0), GHSA-fq7j-8hxj-jfqh (high, the same class; 0.11.1), GHSA-q436-5523-5x82 (medium, escape sequences in todo text; 0.10.0).
**What it installs:** a Claude Code plugin with one skill, `hud`; no hook, command, agent, MCP or LSP server. Files: the plugin cache, and `~/.claude/plugins/claude-hud/` (the launcher `statusline.mjs`, `config.json`, `heartbeat.json` holding the last status payload, `data/`, `stripped/`). It needs Node 22.18 or newer (24.22.3 here) and git. Read in its source at the tag: no network call; usage figures come only from the `rate_limits` field Claude Code passes in; it does not read `.credentials.json`. Two display options, `showAuth` and `showAuthUser`, read the account block of `~/.claude.json`: setup writes both `false` and `agents-check` fails if either is on. The `hud` skill can file a public issue through `gh` (`hud report`), only when asked.
**Beside Orca:** the status line command becomes this repo's wrapper, `deploy/wsl/meridian-claude-hud.sh` (own design): it hands the payload to Orca's reporter, detached, then prints claude-hud's lines, or one plain line if claude-hud prints nothing. Orca 1.4.257 rewrites only a status line command that names its own script (read in its server bundle), so it leaves the wrapper alone.
**Always-on context:** the skill's name and its 250-character description in each session's skill list; not measured in tokens. Each status render starts Node: 140 ms here for the wrapper with claude-hud (three runs), in every Claude Code pane, workers included.
**With and without:** no A/B run was made; a display is not scored on a task. No measured benefit is claimed.
**Decision:** adopted on the owner's instruction of 2026-11-13. `check_claude` now allows three plugin names and still refuses a fourth.
**Install:** `deploy/wsl/setup.sh claude-hud`: adds the marketplace at `jarrodwatts/claude-hud#v0.15.0`, stops unless the checkout is the pinned commit, installs `claude-hud@claude-hud` at user scope, copies the launcher and the wrapper, writes the config once, and sets `statusLine` unless it runs some other command. Run on this machine 2026-11-13; `agents-check` passes.
**Removal:** `claude plugin uninstall claude-hud@claude-hud --scope user && claude plugin marketplace remove claude-hud`, delete `~/.claude/plugins/claude-hud/` and `~/.local/bin/meridian-claude-hud`, remove `statusLine` from `~/.claude/settings.json`, then `deploy/wsl/setup.sh orca` puts Orca's reporter back. Drop the name from `claude_settings` and `check_claude`, or the check fails.
