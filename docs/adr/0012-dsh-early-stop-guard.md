## Need

A DeepSeek Harness (dsh) agent can end a turn on text that announces its next step without making the tool call; in a headless one-shot run that ends the run with the work unfinished. Fewer such stops is the guard's only claimed benefit; it leaves false "done" claims alone (its README, lines 171-181). How often such stops happen on this repository's tasks was not known before R2; in R2 none happened in either arm (Results).

Existing holders, and how far, from the assessment and the re-check: dsh-base mounts dsh's goal loop (`dsh-goal`, `goal-round-driver`, `command-goal`, `tool-goal`; 256 rounds by default), which continues a session while a goal is active, so it does this job at round granularity once a goal is set, and the re-check calls it a partial overlap; headless cannot issue `/goal` (no command adapter), but its `create_goal` tool is in both arms. In `dsh-tui`, Orca's row `orca-agent-hooks` mounts `@deepseek-ai/dsh-hooks-claude-code` 0.2.2-rc.1 (`UPSTREAM.md`), which listens on the guard's seam (`agent/turn-stopping` + `agent.steer`) with no cap on consecutive forced continuations; Orca's hook configuration was not read, so whether its Stop hook ever forces a continuation is not known. Both overlaps are partial and stated, not ruled on.

## What it installs, writes and sends

- Read in all of `lib/` at the pin by the assessor and the re-check, and all 13 files again by each measurement before loading. One Cordis row `early-stop-guard` (inject `llm`) with listeners on `agent/turn-stopping`, which dsh awaits before the turn closes, `turn/end` and `dispose`. No tool, skill, command, system-prompt section, MCP server, child process, telemetry or update check; it runs as host code outside the workspace sandbox.
- It acts only when a turn's last step had no tool call and an earlier step did. Regexes tuned to Chinese sort the last assistant text: only `forward` text goes to a judge; `wait`, `ask`, `done` and `gray` end the turn with no model call. English narrations such as "I will run ruff and pyright next" sort as `gray` and end the turn unjudged.
- Judge chain: first `api.bamboonode.dev`, a third-party endpoint that needs a key and is skipped without one; then one separate request on the session's own model and key (up to 600 output tokens), absent from the session log and from `--json` usage. On "continue" it adds a user-role steer message, at most 3 per turn.
- Writes `<home>/.dsh/early-stop-guard/events.jsonl` under the home directory, not `DSH_HOME`, on by default, each record holding up to 240 characters of assistant text; `secrets.json` (plaintext keys) only if a key is posted to its `/secret` route, which exists only with a connection service.
- dsh's package-inventory metadata, which would name the plugin in every request, is off here: the home patch from `deploy/wsl/setup.sh` disables `plugin-package-inventory-deepseek`.

## Decision

Not adopted, by the rule fixed before the runs: 3 of 3 successes in each arm leave clause 2 unmet, and the with arm's cost per success was 1.607 times the without arm's, although the guard billed nothing and added nothing to any request. The guard's steer and judge paths were never exercised, because R2 produced no premature stop in either arm: the series says nothing about what the guard does when one happens. The static evidence adds no ground to install it: no outcome evidence upstream (100 stubbed unit tests, five example probabilities, an unpublished 13-sample set from another harness), no licence text, one author with one day of commits, triage that lets common English narrations end the turn unjudged, and a decision log that probably cannot be turned off. Nothing changes: no profile, `cordis.patch.yml`, `setup.sh` or `check_dsh` line.
