# DeepSeek Harness with/without method for ADRs 0009 to 0012 (plan 8.6)

This sheet is a description, revised on 2026-11-13 after the series; each ADR's pre-registration and scripts record what its series ran, and win where this sheet differs.

For dsh 0.2.2-rc.1 (npm `@deepseek-ai/dsh`, tag `dsh-v0.2.2-rc.1` = `66491b05`, a prerelease) in the `meridian` distro, where the owner's profile `dsh-tui` is dsh-base plus dsh-tui 0.20.0 and Orca's hook packages. The A/B profiles start from dsh's shipped headless template, not `dsh-tui`, so only the delta of an addition carries over to `dsh-tui`, never the absolute figures. Every run first checks that `dsh --version` is exactly 0.2.2-rc.1 (dsh updates itself) and stops otherwise. dsh is graded on R2 of [ab-tasks.md](ab-tasks.md).

## Always-on: the first request, captured (no key, no model call)

- Profiles from the headless template in a scratch `DSH_HOME`, with a scratch `HOME`, `DSH_AGENTS_HOME` and `TMPDIR`, `DSH_TELEMETRY_DISABLED=1`, and `DEEPSEEK_API_KEY` and `DSH_SYSTEM_PROMPT` unset before a placeholder key is set; nothing under `~/.dsh` changes on this route.
- dsh runs without a network and with `DEEPSEEK_BASE_URL` aimed at a local stub that records the first request and refuses it: ADRs 0009 and 0010 used `unshare -rn` and a stub answering 401, ADRs 0011 and 0012 `bwrap --unshare-net` and a stub answering 400.
- The probe `Reply with exactly the word OK. Do not call any tool.`, 3 runs per arm in the order a1 b1 b2 a2 a3 b3, on the task base `96e82e6`. The request is split into system text, tools and messages and counted offline with o200k_base, a proxy for DeepSeek's tokenizer. The bases differ by ADR, and each ADR names its own: prompt texts with the probe (0011: 5,825 without; 0012: 5,835, its working directory 21 characters longer), the raw request body (0009: 6,003), or prompt texts without the probe (0010: 5,812). The session log alone undercounts the request.

## Real task: temporary profiles in the owner's dsh home (ADRs 0009, 0011 and 0012)

- The owner allowed temporary `ab-` profiles under the dsh home for the runs of 2026-11-13; dsh loaded its own key from its own home, and no agent opened, copied, searched or exported it. A scout fixed the route first and billed one 5,357-token smoke run.
- Profiles: dsh writes its headless template into a scratch home (`--from-default-profile headless --dump-config`); `package.json` (renamed), an empty `cordis.patch.yml` and `pnpm-workspace.yaml` are copied into `~/.dsh/profiles/ab-NNNN-a` and `-b`, with neutral names of equal length and the arm key kept outside the run folders. dsh adds a `cordis.yml` at each boot. The profiles are removed after the series.
- The addition is loaded only in the with arm, by that profile's own `cordis.patch.yml` row whose `name` is the absolute path of its module in a clone outside `~/.dsh`; every file of it is read before the first load, and no `dsh plugin` command runs. Before run 1 both arms' config dumps are diffed: only the addition's rows may differ.
- A shared overlay is the last `--patch` in both arms. It switches off the `orca-agent-hooks` row the home patch inserts into every profile, keeps uploads off, sets `deepseek-flash` with thinking at effort max, moves sessions and storages into the run folder and caps goal rounds (`goal.defaultMaxGoalRounds`, 8 in the real tasks); dsh's goal tools stay on in both arms.
- Each run of ADRs 0011 and 0012: `bwrap --dev-bind / /` with a tmpfs over `/mnt`, `/run/WSL` and the real home, then read-only binds of `~/.local`, the addition's clone and `/mnt/wsl/resolv.conf`; `~/.dsh` bound read-only with only the run's own profile writable; `env -u DEEPSEEK_API_KEY -u DSH_PERMISSION_MODE -u DSH_SYSTEM_PROMPT` with `HOME`, `DSH_AGENTS_HOME` and `TMPDIR` in the run folder, `DSH_TELEMETRY_DISABLED=1` and `DEEPSEEK_BASE_URL=https://api.deepseek.com/anthropic`; `timeout --signal=INT --kill-after=60 1800`; `dsh --profile <p> --patch <overlay> --json --permission-mode workspace-write --approval-policy never --add-dir <run cache>`, the brief on stdin.
- ADR 0009's runs differed (its Method): `--permission-mode read-only`, and only named home folders hidden, so the rest of the home and the dsh home, its key file included, stayed readable.
- Under workspace-write dsh runs bash in its own bubblewrap profile (read-only root, private `/tmp`, writable checkout and added folders), and "never" rejects every escalation; caches (`UV_CACHE_DIR`) go under the added folder, and `PYRIGHT_PYTHON_IGNORE_WARNINGS=1` stops pyright's version lookup. In the 0011 and 0012 runs uv, ruff, pyright and pytest all ran under this mode.
- Each checkout holds the task's base commit only, with `tests/` from the fix commit staged: 0011 cloned the base at depth 1, 0012 cloned a base repository holding the base and one local commit with those tests. The fix commit is in no repository a run can reach.
- Before each run a guard checked that nothing listened on the paper Gateway's port and that no Gateway process ran; it sees only the distro.

## What the runs taught

- Hiding `/mnt` also hid the resolver file: in this distro `/etc/resolv.conf` is a link to `/mnt/wsl/resolv.conf`, so no host name resolved. ADR 0012's first run, a1, ended after 18 s with `TRANSPORT`, 0 tokens and no model output, and is void; its amendment 1 shows that one file again in both arms, and a6 took a1's slot. ADR 0011 found the fault in a smoke run before its series and fixed it in its pre-registration.
- A dsh shell has network access: no dsh mode confines the network or reads, and the wrapper did not cut the network, because the model needs DeepSeek's API. A task whose base is public lets the model fetch the fix: in ADR 0009, 4 of its 6 dsh runs are void, 2 in each arm, because the model fetched the public repository's later history. A later dsh task needs a network bound that leaves only the provider reachable, or a private base.
- Not masked inside a run of ADRs 0011 and 0012 (for ADR 0009 see the bullet above): the network, the file system outside the home, and `~/.dsh` with the key file, which the model's read tool and shell can read in every mode. Tool subprocesses do not get the key (dsh drops names matching `KEY|PASSWORD|SECRET|TOKEN` and all `DSH_*` from their environment), but an addition's in-process code can read dsh's environment. After each run: gitleaks on the run folder, a count of files holding a key-shaped string, and a count of tool calls that touch the dsh home; any hit voids the run and stops the series. In ADRs 0011 and 0012 every run had 0 new findings and 0 such files or calls.
- Under `~/.dsh` the only lasting changes were the `profiles` folder's time and `profiles/dsh-tui/cordis.yml`, rewritten several times that morning with the same 223 bytes, also when no run was active; the runs had the dsh home read-only, and the writer is not identified. Nothing was undone by hand.
- The three series ran at the same time on one key and one dsh home. Billed tokens do not depend on that; wall-clock seconds may.

## Counting

- Success: dsh exit 0, final reason `completed`, and the task sheet's grade passes on the run's patch replayed into a fresh checkout. Exit 124 or 137 is a timeout.
- Billed tokens: input, cache-read, cache-write and output over every model call of every session log of the run (`session.v4.jsonl`, sub-agents and compaction summaries included). The `--json` stream covers the root agent only. A model call without usage makes the run incomplete. About nine tenths of what the real tasks billed were cache reads.
- The grade runs outside the agent with an empty `HOME`; ADR 0012's grade also ran in its own namespace with no network and the real home hidden.
- Headless has no `/goal` command, but `create_goal`, `get_goal` and `update_goal` are in both arms' tools; dsh accepts a goal the model creates in the turn of the brief.
