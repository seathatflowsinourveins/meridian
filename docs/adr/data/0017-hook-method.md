# No-model hook protocol check, 2026-11-13

The owner's revised rule retired per-item model A/B series. [0017-hooks.py](0017-hooks.py) feeds runtime-defined inputs to RTK 1.2.0's native hook processors, first Codex, then Claude, and executes each returned replacement. [Recorded inputs, responses, settings and results](0017-hooks.json) contain synthetic session/tool values and only public command output. No private transcript was read, no credential was loaded by this script, and no model or Claude session started.

Input authority is the host runtime, not an RTK README example:

- Codex CLI 0.167.2: its [generated PreToolUse input schema](https://github.com/openai/codex/blob/rust-v0.167.2/codex-rs/hooks/schema/generated/pre-tool-use.command.input.schema.json), [output schema](https://github.com/openai/codex/blob/rust-v0.167.2/codex-rs/hooks/schema/generated/pre-tool-use.command.output.schema.json) and [host tests](https://github.com/openai/codex/blob/rust-v0.167.2/codex-rs/core/tests/suite/hooks.rs#L3653) establish the required fields, Bash normalization, command field and updatedInput behavior. The probe checks required/allowed input fields against that downloaded schema, sends default permission mode, and retains the complete response.
- Claude Code: its [official common input example and PreToolUse contract](https://code.claude.com/docs/en/hooks#common-input-fields) define Bash input, command and description fields, session context and JSON response. Synthetic values replace the example's paths/session identifiers. The response uses the documented updatedInput field.

For each runtime, `git status` → `rtk git status`, `uv run ruff check .` → `uv run rtk ruff check .`, and `uv run pyright` → `rtk uv run pyright`. All six processors exit zero. Executed replacements exit 0, 0 and 1 respectively: the same planted type error is still reported. These are successful standalone protocol/command checks, **not a live host-discovery, approval/trust or session-routing proof**. The safety/fidelity veto already prevents adoption, so no claim about unseen host behavior is needed.

Configuration checked by actual init into scratch:

- Codex: `rtk init --codex` writes project `.codex/hooks.json`, with PreToolUse/Bash and command `rtk hook codex`, plus root `RTK.md` and the AGENTS.md reference. No global settings write. Source: [codex.rs](https://github.com/rtk-ai/rtk/blob/v1.2.0/src/hooks/init/codex.rs).
- Claude: `rtk init -g --agent claude --hook-only --auto-patch` writes user-scope `~/.claude/settings.json` **under the empty scratch HOME**, registering PreToolUse/Bash with `rtk hook claude`. It writes no awareness document in hook-only mode. Without `-g`, hook-only prints a warning and exits zero without installing anything; an initial setup attempt exposed this and the recorded run uses the corrected flags. Default non-hook-only setup can additionally write project instructions/extra pipeline hooks, but its base hook is user-scope. Source: [claude.rs](https://github.com/rtk-ai/rtk/blob/v1.2.0/src/hooks/init/claude.rs#L898).
- DeepSeek Harness: no probe or integration, per coordinator direction; its bridge's behavior was not independently investigated in this ADR.

The pinned binary was visible only on each subprocess's PATH. Both scratch integrations and their state are removed with the download folder. The [original guarded model probe](0017-probe.py) is historical evidence, not a pending task; do not use it as the new reproduction recipe. To repeat these protocol probes after [fetching](0017-fetch.py), fetch the pinned Codex input schema from the URL above to the cache filename `codex-pre-tool-use.command.input.schema.json`, run the command measurements first to create the locked scratch environment, then `python3 docs/adr/data/0017-hooks.py`.
