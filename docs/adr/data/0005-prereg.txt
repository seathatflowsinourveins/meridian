RULE AND VETOES (assessment, measurement_protocol.adopt_if, verbatim)
Set before any run. Adopt only if no veto fires in any 'with' run and either (a) 'with' succeeds in at least 2 of 3 runs while 'without' succeeds in at most 1 of 3, or (b) both arms succeed 3 of 3 and 'with' has at least 25% fewer median num_turns and at least 25% fewer median total tokens (its always-on text in every request and all subagent tokens included). Anything else, including equal success at equal or higher cost, stays not adopted. Vetoes: any change under tests/; any tracked or untracked file outside meridian/ and .gitignore (the self-ignored .superpowers/ excepted); any command that starts meridian.ibkr_paper; any package install other than uv; any gh issue or pr create or other post; any listener left on a non-loopback address.

PROTOCOL AND FIXES (verification fact sheet, "Measurement protocol", verbatim)
- **Prep (owner-approved, data only):** clone to `~/src/ab-plugins/superpowers-v7.0.2`, `checkout --detach 22f0b463`, `SP="--plugin-dir …"`.
- **Always-on:** in a worktree at main f65d835, run 3 per arm of `claude [$SP] -p 'Reply with the single word OK.' --max-turns 1 --output-format stream-json --verbose`. Compare the median first-assistant input+cache tokens; cross-check with /context and `plugin details`. The flags exist in 2.1.322; `--max-turns` is documented but hidden from `--help`.
- **R1 (lead-validated):**
  - Setup: worktree at 27aa964, `git checkout 5d51c9c -- tests/`, `uv sync --locked`; the same brief, 3 interleaved runs per arm.
  - Grade: exit codes of `uv run pytest`, `uv run pyright` and `uv run ruff check .`; the diff against 27aa964 outside tests touches only meridian/ and .gitignore; tests/ equals 5d51c9c; git status is recorded.
- **Adopt only if** no veto fires and either (a) with ≥2/3 and without ≤1/3, or (b) both 3/3 and with ≥25% fewer median turns AND total tokens. A one-run miss allows 2 more runs per arm, once.
- **[Fixes:]** limit the veto exception to `.superpowers/sdd/`; add `~/.superpowers` and `git worktree list` to containment; make the vetoes preventive with identical `--settings` deny rules in both arms (deny rules block even under bypassPermissions); record `claude_code_version` per run, or hold it fixed.
Fix (3) in the verification's own words: "identical --settings deny rules in both arms (Bash gh issue create, gh pr create, git push, poetry, pip install, npm install) would prevent the vetoed actions."

DEFAULT RULE (ab-claude-code.md line 38, verbatim)
Adopt only if the arm with the addition passes in at least 2 of 3 runs and the arm without in at most 1; or both pass in at least 2 of 3 and the arm with the addition uses at least 25% fewer median tokens; and in either case the always-on delta is at most 2,000 tokens unless the first condition holds.
Applied here: the assessment's rule (stricter on the second condition: both 3 of 3, turns and tokens) plus the default rule's 2,000-token cap. That combination was settled after the series, not before it: the assessment's rule above has no cap, the method's heading reads "Default adoption rule (an ADR may set a stricter one)", and no record from before the first run says whether the cap applies on top of the assessment's rule. The first dated record that applies it is the measurement notes (file time 2026-11-13 02:03; the series ran 01:37 to 02:00). The decision does not depend on the cap: conditions (a) and (b) both fail.

FURTHER DEPARTURES FROM THE ASSESSMENT'S PROTOCOL (measurement_protocol: always_on, runs_and_metrics, real_task, containment_check). Settled by the runner and the brief before the first run, the same in both arms, but not recorded as departures then; found by reviews on 2026-11-13, after the series. In the first five, the method's choice (ab-claude-code.md, ab-tasks.md) took precedence over the assessment's.
- Always-on prompt: the method's 'Reply with the single word OK. Do not use any tools.' (ab-claude-code.md line 23), not 'Reply with the single word OK.' of the assessment and of the fact sheet quoted above. Both arms used the same prompt.
- Model: claude-opus-5-5 at high effort, the method's, not "the distro default claude-fable-5-2 at high" that the assessment named. claude-fable-5-2, the stack's lead model, was not measured, though a user-scope install would load the plugin for the lead too.
- Brief: ab-tasks.md's R1 brief word for word, without the fixed line the assessment put before it: 'Unattended run: nobody will answer questions; decide and carry on until done. Do not push, and never start the IBKR lane.'
- Order: the method's a1 b1 b2 a2 a3 b3, not the strict alternation "(without-1, with-1, without-2, ...)" of the assessment.
- Tokens: the method's sum over the result's modelUsage, not the assessment's sum over assistant events de-duplicated by message id.
- Always-on cross-checks: /context ran once per run as the method's separate '-p /context' session, before any prompt, and 'plugin details' once. The assessment's /context again after /clear, and its grep -c 'You have superpowers.' over each session transcript (one per startup, /clear and compaction), were not made. That the bootstrap comes back after every /clear and every compaction rests on the hook's matcher (startup|clear|compact), read from the source, not on a measurement.
- First-request input tokens per R1 run (runs_and_metrics): the runner recorded them (first_assistant_input_all in each run's metrics.json), but the series did not report them. Added to 0005-results.json after the series: 21,882 in every run without, 24,058 in every run with, the same +2,176 as the always-on runs.
- Containment: listings of ~/.claude/plugins/data and ~/.claude/plugins/cache before and after each run replaced the assessment's check that "sha256sum ~/.claude/settings.json ~/.claude/plugins/installed_plugins.json is unchanged across the with-arm runs"; neither file was hashed. The assessment's after-each-run grep of the Bash commands for vetoed actions (gh issue or pr create, poetry, pip or npm install, start-server.sh, --host 0.0.0.0) and its "ss -ltnp shows no node listener" were not run after each run: one grep over each run's tool calls was made once after the series (2026-11-13 04:05 ET) and found none, and no listener check was made.
