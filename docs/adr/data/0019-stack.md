Legacy autopilot, ultrapilot, swarm, pipeline, team and skill-active protection can also continue when their corresponding state is active; bridge availability changes advanced Ralph verification.

Upstream `DISABLE_OMC` / `OMC_SKIP_HOOKS=persistent-mode` or `stop-continuation` skips this hook altogether ([L82–96](https://github.com/Yeachan-Heo/oh-my-claudecode/blob/b93059fb7c10ae28934a0bc950e26c9a17437a94/templates/hooks/persistent-mode.mjs#L82)); there is **no general owner-question / Orca-ask setting**. Its skill prose includes autonomous assumptions. Meridian appends explicit overrides: owner boundaries first; worker uses Orca ask, not local questions; `[MERIDIAN_WAIT]` ends a boundary decision turn; no tmux/provider fleet; no MCP workaround. False-positive stops are possible, and natural language without the marker cannot be proved to describe every boundary question. The ask latch itself is mechanical and session-specific, verified against the installed hook.

### Hook process cost and final layout

Measured on this shared Linux runtime, Node v24.22.3, Python 3.14.4: 32 fresh-process calls per variant/event after one untimed warm-up. Payload: synthetic session/cwd/transcript, a Bash pytest command string, description, 60 output lines, prompt and last-assistant message. The command in the payload is data, never executed. No active workflow in the timing run; the separate synthetic stage probe tests active persistence. Public version-check caches are warm for SessionStart.
