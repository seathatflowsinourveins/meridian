## Setup surface and switches

[CLI L1336–1401](https://github.com/Yeachan-Heo/oh-my-claudecode/blob/b93059fb7c10ae28934a0bc950e26c9a17437a94/src/cli/index.ts#L1336): default standalone fallback when no enabled plugin supplies skills; `--no-plugin` forces bundled skill copies; `--plugin-dir-mode` relies on runtime `--plugin-dir` for skills/agents but still installs HUD, hooks and CLAUDE.md; `--no-plugin` wins if both flags appear. Project-scoped plugin operation skips global settings/HUD; our CLI setup is user scope, located by `CLAUDE_CONFIG_DIR`.

Chosen: `setup --no-plugin --force --quiet </dev/null`. `--force` merges other hooks; without it, events already held by Orca are skipped. **Never use `--force-hooks`: it discards other hooks.** The advertised `--skip-hooks` option is not passed into `installOmc()` at this pin; it is not a working containment switch ([merge L1051–1105](https://github.com/Yeachan-Heo/oh-my-claudecode/blob/b93059fb7c10ae28934a0bc950e26c9a17437a94/src/installer/index.ts#L1051)). `--force` also overwrites same-named legacy agents and bundled skills; inspect existing user assets before the lead's install. The source does not provide a conflict-free namespace for every standalone role.

Writes observed under the scratch Claude home:

- `agents/*.md`, `skills/*` (including references and OMC ownership markers), `hooks/*.mjs`, `hooks/lib/*`, `hooks/find-node.sh`; no `commands/` entries (deprecated). Setup also creates compatibility shims where applicable. [Copy path L2583–2729](https://github.com/Yeachan-Heo/oh-my-claudecode/blob/b93059fb7c10ae28934a0bc950e26c9a17437a94/src/installer/index.ts#L2583).

## Network surface

Setup's selected path copies local package files; downloading npm packages contacts the registry, and research downloaded public GitHub source. The standalone SessionStart checks `https://registry.npmjs.org/oh-my-claude-sisyphus/latest` and `https://registry.npmjs.org/@anthropic-ai/claude-code/latest`, with 24-hour caches and two-second fetch timeouts ([template L567–705](https://github.com/Yeachan-Heo/oh-my-claudecode/blob/b93059fb7c10ae28934a0bc950e26c9a17437a94/templates/hooks/session-start.mjs#L567)). Those requests carry package names, not repository/task text. `silentAutoUpdate:false` and `autoUpgradePrompt:false` are not network-off switches: the version requests remain. No new service or account is configured.

Opt-in notification senders can send session/task material to Discord, Telegram, Slack, configured webhook URLs or command gateways ([dispatcher](https://github.com/Yeachan-Heo/oh-my-claudecode/blob/b93059fb7c10ae28934a0bc950e26c9a17437a94/src/notifications/dispatcher.ts)); `OMC_NOTIFY=0` returns before notification processing ([notifications/index.ts L132–136](https://github.com/Yeachan-Heo/oh-my-claudecode/blob/b93059fb7c10ae28934a0bc950e26c9a17437a94/src/notifications/index.ts#L132)). OpenClaw is also explicitly off. The standalone SessionEnd bridge normally runs only for a factory ledger ([template L28–78](https://github.com/Yeachan-Heo/oh-my-claudecode/blob/b93059fb7c10ae28934a0bc950e26c9a17437a94/templates/hooks/session-end.mjs#L28)); Meridian suppresses that event's OMC program entirely, preventing its cross-session chain launcher ([processSessionEnd L961–994](https://github.com/Yeachan-Heo/oh-my-claudecode/blob/b93059fb7c10ae28934a0bc950e26c9a17437a94/src/hooks/session-end/index.ts#L961)). Orca's separate SessionEnd hook still runs. Optional provider launchers, notification setup, factory chains and update commands remain shipped but are outside the admitted lifecycle; the instruction forbids their use as a fleet. This is not an assertion that the entire package has no network-capable code.

It differs substantially from the plugin's larger `hooks/hooks.json`; this stack does not claim the plugin's hooks are installed.

| Event | Program | Effect |
|---|---|---|
| UserPromptSubmit | keyword-detector.mjs | Detect/activate modes; named profile validation and activation before generic triggers. |
| SessionStart | session-start.mjs | Restore OMC state/context, check versions and update notices. |
| PreToolUse | pre-tool-use.mjs | Delegation advice and skill-active protection state. |
| PostToolUse | post-tool-use.mjs | Tool/todo feedback and `<remember>` notepad capture. |
| PostToolUseFailure | post-tool-use-failure.mjs | Sanitized failure state for subsequent retry guidance. |
| Stop | persistent-mode.mjs | Mode persistence and named-profile advancement. |
| Stop | code-simplifier.mjs | Opt-in cleanup delegation, off by default. Meridian's stop guard covers it too. |
| SessionEnd | session-end.mjs (async) | Registered but suppressed by Meridian: upstream forwards to its bridge only when a factory-chain ledger exists, which can spawn work after the session; Orca owns that job. |

[Standalone Stop L1280–1840](https://github.com/Yeachan-Heo/oh-my-claudecode/blob/b93059fb7c10ae28934a0bc950e26c9a17437a94/templates/hooks/persistent-mode.mjs#L1280) reads mode state and blocks Stop to continue an active mode belonging to the project/session. It skips context-limit stops, user aborts, authentication failure, normal hook reentry, cancellation, stale ordinary state (two hours) and `awaiting_confirmation`; the reentry path can delegate reviewer-state progress. Ralph increments iterations and **extends its maximum by ten** when reached; a configured hard limit deactivates it and emits one final block. Named profiles validate the immutable descriptor and transcript boundary; only a matching assistant `Signal: PIPELINE_<STAGE>_COMPLETE` after activation advances a stage. Final QA deactivates the workflow and emits one completion block; the next Stop releases. Corrupt descriptor/evidence blocks with recovery guidance. Legacy autopilot, ultrapilot, swarm, pipeline, team and skill-active protection can also continue when their corresponding state is active; bridge availability changes advanced Ralph verification.

Upstream `DISABLE_OMC` / `OMC_SKIP_HOOKS=persistent-mode` or `stop-continuation` skips this hook altogether ([L82–96](https://github.com/Yeachan-Heo/oh-my-claudecode/blob/b93059fb7c10ae28934a0bc950e26c9a17437a94/templates/hooks/persistent-mode.mjs#L82)); there is **no general owner-question / Orca-ask setting**. Unlike Codex's stored hook hashes in ADR 0008, this user-settings installation has no self-written Codex hook-trust entries. Claude's existing managed policies still apply.

The always-on upstream [instruction block](https://github.com/Yeachan-Heo/oh-my-claudecode/blob/b93059fb7c10ae28934a0bc950e26c9a17437a94/docs/CLAUDE.md) requests delegation, permits direct writes to agent settings, suggests AskUserQuestion, requires verification and cancellation when blocked. Its skill prose includes autonomous assumptions. Meridian appends explicit overrides: owner boundaries first; worker uses Orca ask, not local questions; `[MERIDIAN_WAIT]` ends a boundary decision turn; no tmux/provider fleet; no MCP workaround. False-positive stops are possible, and natural language without the marker cannot be proved to describe every boundary question. The ask latch itself is mechanical and session-specific, verified against the installed hook.

## Scratch runtime evidence and always-on estimate

Scratch root was a new `~/.cache/meridian/omc-0019/`. Source clone at the pin; npm lock integrity matched the pin, and all eight installed hook templates plus the instruction source matched the git pin byte for byte; npm installed under `npm/` with cache inside that root and `--ignore-scripts --no-audit --no-fund`. Only real settings key **names**, Orca hook entries and `statusLine` were copied; no authentication file or credential value. Scratch settings were seeded with the last two; every original Orca group and exact `statusLine` survived `setup --no-plugin --force`. The actual CLI on this runtime was Claude Code 2.1.325; Node v24.22.3, Linux with flock.

Run setup in a scratch working directory with **all** these overrides (in addition to the chosen prewritten config):

```sh
CLAUDE_CONFIG_DIR="$T/claude" OMC_HOME="$T/omc-home" OMC_STATE_DIR="$T/state" \
  CLAUDE_MCP_CONFIG_PATH="$T/empty.json" OMC_MCP_REGISTRY_PATH="$T/empty.json" \
  CODEX_HOME="$T/codex" XDG_CONFIG_HOME="$T/config" \
  node "$T/npm/node_modules/oh-my-claude-sisyphus/bin/oh-my-claudecode.js" setup --no-plugin --force --quiet </dev/null
```

`empty.json` contains `{}`. `meridian-omc.py prepare` writes the chosen config before setup; `configure` wraps hooks and appends precedence instructions afterwards; `check` verifies them. This uses upstream's own standalone example, not a rewritten installer. The retained [probe](0019_probe.py) receives that scratch root and produces [results](0019-results.json): disabled prose, explicit activation, owner question stop, Orca ask latch, four stage transitions, inactive completion and final release. Its transcript and task are synthetic; no model, agent, broker or order runs. Offline repository tests independently exercise drift rejection, preservation, idempotency, interleaved session latches and disposable dispatch probing.

Failures, not hidden: the first activation used a transcript outside the required `CLAUDE_CONFIG_DIR/projects/<...>/<session>.jsonl`, so upstream correctly refused it. The first setup/probe omitted `OMC_STATE_DIR`; OMC's non-Git fallback wrote `~/.omc/template-version.json` and the known synthetic `scratch-workflow` session state. Those exact probe-created files and now-empty directories were removed; the corrected probe contains all state under scratch. A repeated setup initially added an empty upstream user-customization header; the adapter now removes only that empty trailing header, and settings/instructions/config are byte-identical across repeated setup+configure. No real `~/.claude` file was changed. This omission was fixed in the install step as well.

## Installation and removal

After merge the lead runs `deploy/wsl/setup.sh omc`, then `deploy/wsl/setup.sh agents-check`; a new Claude session loads it. `cmd_claude` invokes the same idempotent step. The pin is checked by the existing `npm_pinned` registry integrity function before installation; npm verifies that tarball. Machine-wide MCP policy is checked after setup. No real installation was run for this ADR.

Per-worktree `.omc/` is in this repository's shared `info/exclude` (the setup step adds it idempotently on each clone) and joins the agent-configuration forbidden folders; no runtime state belongs in commits. The only new project configuration exception is exact `.claude/omc.jsonc`, with a test requiring the exact schedule and no execution keys. `*.jsonc` is classified as counted configuration; no budget increased.

There is **no standalone `omc uninstall` command** at this pin (`src/cli/index.ts`); the documented `/plugin uninstall oh-my-claudecode@oh-my-claudecode` removes a plugin installation, which this is not. To remove this stack:

1. End attended workflows / close their sessions; preserve needed `.omc/` plans and run evidence locally. Remove OMC hook entries by their exact managed program paths from user settings, keeping every Orca group and `statusLine`. Remove `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS` only if no other owner configuration needs it, and OMC-only environment keys.
2. Remove only the `OMC:START`…`OMC:END` and `MERIDIAN-OMC:START`…`MERIDIAN-OMC:END` blocks from user CLAUDE.md. Preserve all user text/backups.
3. Before `npm uninstall -g oh-my-claude-sisyphus`, inventory package agents, the installed skills' OMC ownership markers and standalone hook/template filenames from the pinned package. Delete only unchanged package-owned copies from user `agents/`, `skills/` and `hooks/`; retain edited files for the owner, and do not delete other tools' directories. Remove `.omc-version.json`, OMC-owned `.omc-config.json` keys, the keywordDetector disabled list in user JSONC, Meridian's adapter/snapshot/latches, and OMC-only caches after inspecting ownership. Do not delete an entire user settings/config file.
4. Remove the project profile and `.omc/` per-worktree state when no longer needed, and this task's `/.omc/` exclude line. Remove the setup/check integration in the same change or `agents-check` correctly fails. claude-hud and Orca require no reinstallation.

Not done: real install; signed-in model lifecycle or team run; provider token delta; tmux runtime; MCP or state-tool cancellation; cross-family review; push/PR/merge. The lead owns installation and the reviewer owns cross-family assessment.
