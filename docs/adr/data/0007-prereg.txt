## Pinned install and removal (Codex 0.167.2)
- Documented route (learn.chatgpt.com/docs/plugins, read 2026-11-13): `codex`, then `/plugins`; no CLI install, pin or remove commands. CLI (cli/src/plugin_cmd.rs, marketplace_cmd.rs): `codex plugin add <plugin>@<marketplace>`, `codex plugin remove ...`, `codex plugin marketplace add|list|upgrade|remove`. Curated names are reserved (core-plugins/src/lib.rs:47-48, marketplace_policy.rs:343), so `marketplace add openai/plugins --ref <sha>` is refused; the only pin is a vendored local marketplace.
- Blocked on this machine: /etc/codex/requirements.toml (deploy/wsl/meridian.user-data:68-77 at 9c5daaa; agents-check enforces it, setup.sh:490-509) pins `plugins`, `apps`, `skill_mcp_dependency_install`, `memories` = false and has an empty `[mcp_servers]`. Observed 2026-11-13 in a throwaway CODEX_HOME whose config.toml set plugins = true: `codex features list` reports plugins false; `codex plugin marketplace add <dir>` writes the entry, then `codex plugin add dummy@v3-dummy` fails "not found in marketplace" and `codex plugin list` shows none. Docs: an empty `mcp_servers` "disables all MCP servers"; plugin MCP servers are filtered the same way (core/src/config/mod.rs:1839-1856, 2290-2310).
- Removal if ever installed: `codex plugin remove codex-security@<marketplace>`, `codex plugin marketplace remove <name>`, delete $CODEX_HOME/state/plugins/codex-security and $CODEX_HOME/.tmp/plugins*.

## Measurement protocol
- Real task R4 (ab-tasks.md): worktree at 96e82e6; brief verbatim "Review `meridian/boundary.py` for ways a login that is not a paper login could pass its checks. Report what you find and change nothing."; graded on whether the [DEFAULT]-inheritance defect is reported plus real/false findings against 39cb68ea3241caeececb6db0521a12ea2fa92fee. Judgement-graded, not exit-code graded. Rules: neutral a/b names, 3 runs per arm interleaved a1 b1 b2 a2 a3 b3, +2 per arm on a one-success gap or a 2-2 tie, brief sha256 recorded.
- Not executable under this machine's policy: both arms would run with plugins off. Running it needs the owner to change machine policy (requirements.toml, user-data, agents-check) and to sign in to new homes; no agent may do either. Runs done: none.
- Adoption rule (stated up front): adopt only if the preconditions hold (owner lifts the pins, vendored pinned copy, bundled advisories fixed or accepted) and D(with) >= 2/3 while D(without) <= 1/3, median false findings no higher, median total tokens <= 3x, measured always-on delta <= 1,500 tokens.

## Provisional verdict
- Not adopted. Machine policy blocks it (plugins and every MCP server pinned off), the documented route follows HEAD, codex-security here is an old, relabelled copy with high-severity bundled advisories, it adds about 1,283 tokens (59% of AGENTS.md) to every Codex session, and its job is already covered by /review, review-agent, /codex:review and Claude Code's /security-review.
