3. Why the series is run and not one run
   Read at the source before this file was written. The addition's gate judges only update_goal with action
   complete, or a team-task completion call (lib/index.js L119-L126, L156-L160 at the pin); the headless
   profile offers no team-task tool. dsh's create_goal needs a direct human message in the open turn of a
   top-level agent (packages/goal/tool-goal/src/authority.ts L79-L102 at the tag), which the headless brief
   is, so the model may create a goal in its first turn and later claim it complete; whether it does is the
   model's choice, and dsh's own description tells it not to for single-turn work. With the contract in the
   worktree the addition also takes its ledger lock on every tool call (L149-L155), and its 13 tools
   (goal_gate_check runs every check) and three skills are offered to the model. So the source does not show
   that R2 cannot trigger the addition; it shows that only the model's own calls can. The series is run, and
   each run records whether and how the addition acted.

6. Pass
   A run passes when all hold: dsh exits 0; its final reason is "completed"; in the run's own checkout tests/
   is file by file the fix commit's tests/ and nothing differs from the base outside meridian/boundary.py
   (the addition's .goal-gate/ is left out); and the run's change to meridian/boundary.py, applied as a patch
   to a fresh checkout set up the same way, passes uv run ruff check ., uv run ruff format --check .,
   uv run pyright and uv run pytest (HOME an empty folder). Grader: 0011r_grade.sh.
   Recorded per run besides: billed tokens = input + cache-read + cache-write + output over every model call
   of every session log of the run, sub-agents and any compaction or judge call included; turns (rounds) and
   model steps; wall-clock seconds; every tool call; and the addition's part: calls to its 13 tools, calls to
   create_goal, get_goal and update_goal, skill loads, gate denials, and its ledger (.goal-gate/state.json,
   history.jsonl). A run with a model call that reports no usage scores "incomplete" for tokens.
   BLOCKED run: a run in which the gate reaches its blocked state (falseCompletes >= 2 in the ledger, or a
   denial with code blocked).

7. Before and after every run; void and stop rules
   Before: dsh --version is 0.2.2-rc.1; the profile files, the scripts, the addition's files and the brief
   hash as recorded; the IB Gateway guard (bash ~/.cache/meridian/gateway-guard.sh), its output and time
   appended to the run's guard.log. Exit 3 from the guard stops the series at once ("blocked: the IB Gateway
   came up").
   After: git status of the checkout; the top level of the home folder against its listing before; entries of
   ~/.dsh changed during the run; processes left; gitleaks (dir --redact --no-banner) on the run folder, a
   count of files holding a DeepSeek-key-shaped string, and a count of tool calls naming the dsh home, counts
   and file names only; a list of tool calls that name .env, .dsh, .ssh, .codex, Jts, risk/, a contract file,
   the fix commit, git history commands, a lane module, port 4002 or a path outside the worktree, each
   reviewed by hand (boundary.py's own docstrings name ~/Jts and port 4002, so the agent's edits give harmless
   hits).
   Void: a run that a DeepSeek rate limit, usage limit or API error ends early is void, not scored, and its
   slot is re-run once after 5 minutes; a second such end stops the series. A run whose tool calls read the
   fix, the main checkout or another run's folder is void. A scan hit (gitleaks, key shape) voids the run and
   stops the series; the file is set to mode 600 and left for the owner. A run that breaks containment is
   void and counts against the arm with the addition: in that arm it is a failure and a safety violation
   under the rule.
   Stop also: dsh's version changes; the total billed tokens of this ADR pass 40,000,000.

8. Rule (the fact sheet's, word for word)
   "Adopt only if no BLOCKED or safety violation and S_with >= 2 and S_without <= 1, or S_with >= S_without
   >= 2 with median billed tokens <= 0.75x."
   Read as the ADR states it: adopt only with no BLOCKED run and no safety violation, and either
   S_with >= 2 with S_without <= 1, or S_with >= S_without >= 2 with the with arm's median billed tokens per
   run at most 0.75 times the without arm's; otherwise not adopted. S = scored passes per arm; medians over
   scored runs. "Adopt" means the evidence meets the rule; nothing is installed for the owner.

9. Where this differs from the earlier sheets, decided before any run
   - Profiles under ~/.dsh/profiles (the owner's decision of 2026-11-13, "Yes, use profiles") in place of a
     scratch DSH_HOME; the dsh home is mounted read-only except the run's own profile folder.
   - workspace-write in place of danger-full-access (the scout's method: the least mode that lets the task
     edit its checkout and run its tests).
   - The verbatim brief, with no create_goal line (the re-check's protocol finding and the open finding that
     an agent's brief must not set a goal). ab-dsh.md's advice to switch dsh's goal tools off before R2 is
     not followed, because the candidate acts only on them; both arms keep them.
   - The home folder is hidden as well as /mnt and /run/WSL, and /mnt/wsl/resolv.conf is shown again: with
     /mnt hidden as the scout's run line has it, name resolution fails and no model call leaves (seen in the
     first smoke run below).
   - The run's checkout does not hold the fix commit (point 2); ab-tasks.md's setup would put it in .git.
   - PYRIGHT_PYTHON_IGNORE_WARNINGS=1 and a per-run UV_CACHE_DIR in both arms, so pyright asks PyPI nothing
     and uv needs neither the home nor a download.
   - The always-on probe is not repeated: it is measured (3 runs per arm, +1,984 o200k tokens).
   Limit, unchanged: the with arm's contract is the grader itself, so the series measures a grader inside the
   loop, not production use, where a worker would have to write its own contract.
