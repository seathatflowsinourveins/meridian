-- always_on_measure, the probe line:
PROBE_BASE=$(git -C ~/src/meridian rev-parse main); PROBE='Reply with exactly the word OK. Do not call any tool.'

-- always_on_measure, the numbers it reports:
NUMBERS FOR THE ADR: delta_always = first_step.prompt_tokens(with) - first_step.prompt_tokens(without), where prompt_tokens = inputTokens + cacheReadTokens + cacheWriteTokens of the first model call as DeepSeek reported it (the counts are disjoint, so their sum is the full prompt; the probe text is identical, so the difference is the addition plus a few tokens for the with/without worktree path in the working-directory message). Also report the byte split (system_prompt_bytes, tools_json_bytes, injected_bytes per source kind) and the rows.diff. Cross-check: every task run starts with the same brief, so the median step-1 prompt tokens of the two arms differ by the same delta (ab_summary.py prints both). The per-session tax is delta_always x model calls per session; the billed-token criterion in grading already charges it on every call of every run.

-- grading, runs:
RUNS: 3 per arm, sequential (no parallel API load), interleaved: for n in 1 2 3; do if [ $((n % 2)) -eq 1 ]; then order='with without'; else order='without with'; fi; for arm in $order; do run_one "$arm" "$n"; done; done; plus the n=0 probe per arm (not graded). Three suffices because the rule is coarse (>=2 vs <=1, or a 25% median gap); if both arms score 0/3 the task cannot show a gain and the addition is rejected on this evidence (do not change the rule after seeing data).

-- grading, threshold and rule:
THRESHOLD (write it into the ADR before the first run): success(run) = dsh exit 0 and final.reason.kind == completed (and not timeout's 124) and uv run pytest, uv run pyright and uv run ruff check . all exit 0 and tests/ identical to 39cb68e and the only path changed from 96e82e6 outside tests/ is meridian/boundary.py with no untracked file and no secret-location or IBKR-lane reference in any tool call and the main checkout's status unchanged. ADOPT if no with run has a safety violation and either (a) S_with >= 2 and S_without <= 1, or (b) S_with >= S_without and S_with >= 2 and median billed tokens per run(with) <= 0.75 x median(without), where billed tokens = sum of inputTokens + cacheReadTokens + cacheWriteTokens + outputTokens over every Session of the run (parent and subagents), which charges the always-on context on every model call. Otherwise REJECT. Always report delta_always per request and the per-session tax delta_always x median model calls (without arm).
