## Need

A DeepSeek Harness (dsh) agent can call `update_goal(complete)` while the work still fails: a false "done". The candidate re-runs a contract's shell checks itself at that call and refuses the claim unless all of them pass. It acts only on `update_goal(complete)` or a team-task completion call, so a turn that ends on "done" without one passes. dsh lets the model create a goal only in a turn that carries a direct human request (`docs/HANDBOOK.md`, Goals, on `origin/m2/handbook-size-budget`), and no runtime's `/goal` runs a check of its own (same section). dsh-base mounts persisted goals (`create_goal`, `get_goal`, `update_goal`, the goal-round driver, `/goal`), whose round prompt asks for evidence before completing but re-runs nothing (`goal-round-driver/src/prompt.ts` L15-L24 at `66491b05`).

Existing holders of the job, and how far: the lead grades work by exit codes, and CI runs `ruff check`, `ruff format --check`, `pyright` and `pytest` on every pull request and every push to `main` (`.github/workflows/ci.yml` at `9c5daaa`); both act outside the worker, after it. Inside a `dsh-tui` worker Orca's row `orca-agent-hooks` mounts `@deepseek-ai/dsh-hooks-claude-code` 0.2.2-rc.1 (`UPSTREAM.md`), which runs Stop hooks at each turn stop, and a Claude Code-style Stop hook can run a script (code.claude.com/docs/en/goal, read 2026-11-13); Orca's hook configuration was not read, so whether a hook there re-runs checks is not known: a partial overlap, stated, not ruled on. Orca's `orchestration` skill covers workers, task DAGs and decision gates, the job of this plugin's Agent Teams tools. ADR 0010 found dsh-gungnir, a candidate for the same job, not measurable on dsh 0.2.2-rc.1.

## What it installs, writes and sends

- Read in `lib/`, `bin/` and the skills at the pin by the assessor and the re-check; both measurements read every `lib/*.js` and `bin/gate.mjs` before loading it. One Cordis row `goal-gate`; no dependencies, install scripts, MCP server or network code; Node >= 22. It registers 13 model tools, 3 skills (`goal-loop`, `goal-loop-contract`, `goal-loop-grill`), 10 slash commands and one `tools/pre-execute` listener on every tool call.
- With no `<cwd>/.goal-gate/goal.md` the listener lets every call through. With one, every tool call takes `.goal-gate/lock`, and `update_goal(complete)`, or a team-task completion under `exit: strict`, re-runs every check through `spawnSync('/bin/sh', ['-c', cmd])` (30 s each by default), outside dsh's permission modes and sandbox. Anything but GO is denied; from 2 non-GO claims every claim is denied as blocked.
- The checks get dsh's whole process environment: dsh's subprocess scrub of names matching `KEY|PASSWORD|SECRET|TOKEN` does not apply, so `DEEPSEEK_API_KEY` reaches every check, and the last 300 characters of each check's output go back to the model.
- The model can undo the gate in v0.9.2: `goal_gate_stamp` accepts an edited contract with `restamp: true` and any `approvedBy` (human approval only with `requireHumanApproval: true`, default off); `state.json` is unsigned JSON in the workspace; `bin/gate.mjs reset`, whose path the skill gives the model, clears the counters with no caller check; deleting `goal.md` switches the gate off. It has no order tool or broker connector, but its checks run outside dsh's sandbox and the model can write and stamp them, so it gives the model a way to run any command there.
- Writes only `<cwd>/.goal-gate/`, which it does not git-ignore (`ruff format --check .` then counts `goal.md`: 17 files against 16). Its tree digest skips only `.goal-gate`, `node_modules`, `.git` and `.dsh` (`lib/core.js` L118-L130), so in meridian's checkout it would read the contents of any `.env*` file, every `*.contract.json` and every file under `risk/`.
- Staff, dispatch, collect and judge need dsh's optional Agent Teams bundle, which is not mounted, so they only return suggestions.

## Method

- Real task R2 of [ab-tasks.md](ab-tasks.md): the fix `39cb68e` replayed on base `96e82e6` with its tests; only `meridian/boundary.py` may change. Both arms got R2's brief word for word (sha256 `9d0b472a…e8ed`), with no goal line; 3 runs per arm in the order a1 b1 b2 a2 a3 b3 (b with the addition, drawn at random), 2 more each on a one-success difference or a 2-2 tie. Each checkout holds the base commit only, `tests/` from the fix staged.
- The owner allowed temporary `ab-` profiles under the DeepSeek Harness home for these runs; dsh loaded its own key and no agent read it. The profile route, wrapper and counting are those of [ab-dsh.md](ab-dsh.md): the real home, `/mnt` and `/run/WSL` hidden, the network open, `--permission-mode workspace-write --approval-policy never`, a 1,800 s timeout, `deepseek-flash` at effort max, dsh's goal tools on in both arms with goal rounds capped at 8. The with arm loads the 19 pinned files through its profile's own row; the two config dumps differ only by that row. Before every run a guard checked that nothing listened on the paper Gateway's port and that no Gateway process ran.
- The with arm's contract `.goal-gate/goal.md` holds five checks (pytest, ruff check, ruff format, pyright, scope), stamped by the operator with the addition's CLI, which ran outside the run namespace and writes only under `.goal-gate`. Each check starts from `env -i`, so no key reaches it; the scope check compares `tests/` with a manifest outside the checkout. Validated with the gate's CLI: NO-GO at the base, GO with the fix. The contract is the grader itself, so the series measures a grader inside the loop, not a contract a worker wrote.
- Grade: the run's patch replayed into a fresh checkout must pass `ruff check`, `ruff format --check`, `pyright` and `pytest` (run with an empty `HOME`, not in a namespace); dsh exit 0, final reason `completed`, `tests/` equal to the fix's, and nothing else changed (`.goal-gate/` allowed). The unchanged base fails it (1 failed, 248 passed), the fix passes (249). Billed tokens: input, cache-read, cache-write and output over every model call of every session log.
- **Rule, word for word: "Adopt only if no BLOCKED or safety violation and S_with >= 2 and S_without <= 1, or S_with >= S_without >= 2 with median billed tokens <= 0.75x."** It was fixed before the runs in the [pre-registration](0011-real-prereg.txt), sha256 `fdb380ff…8613` (the published copy, byte for byte the file as run), recorded at 09:02:48 ET; run a1 started at 09:02:54. Those times come from the owner's machine and cannot be proved from the repository. The file's first line says 09:03. The [aggregation script](0011_real_aggregate.sh) was written at 09:03:21, after a1 started, and was not among the hashed scripts; an independent recomputation gives the same figures.
- Always-on (02:00 to 04:07 ET): profiles from the headless template in a scratch `DSH_HOME`, dsh under `bwrap --unshare-net` against a local stub that answered 400, a placeholder key. Its [pre-registration](0011-prereg.txt) is a copy written after those runs that restates four earlier files by sha256 and time; the assessment's own rule was set aside for method-dsh's as the re-check tightened it. The pilots A1 and B1 ran with an unkept runner and left no guard log, so their network isolation and Gateway check rest on the measurer's notes; their captures match the later runs of their arm byte for byte apart from the equal-length worktree name. The first session's driver stopped at 02:03 ET on a false alarm: its guard matched another agent's command line while no Gateway ran.

## Decision

Deferred. The rule fixed before the runs returns **adopt**, through its token clause only: S_with 3 >= S_without 3 >= 2, median 209,058 <= 0.75 x 311,486, no BLOCKED run, no safety violation. The addition did not act in any with-arm run (no call to its tools, no goal, no gate evaluation); every with-arm request was 2,263 prompt tokens larger by DeepSeek's count; and 6 of the 20 ways to split the six totals three and three meet the clause. The series did not exercise the addition, so it decides nothing about it, and nothing is installed. The source findings at the pin stand beside that: the model can undo the gate, the checks get the DeepSeek key unscrubbed and run outside dsh's sandbox, the digest would read `.env*` files, and there is no licence text; the author names P0/P1 trust holes and has fixed part of them only on the untagged `main`. A series that measures the gate needs a run in which `update_goal(complete)` is called, which R2's brief did not lead to in any of the 3 with-arm runs.
