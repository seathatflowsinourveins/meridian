# ADR 0003: Trail of Bits property-based-testing and supply-chain-risk-auditor for Claude Code (plan 8.6)

**Status: not adopted.** Decided 2026-11-13.

This ADR covers 2 additions from one source, as plan 8.6's candidate list names it, and decides each separately. No with/without task was run for property-based-testing: it was decided on its measured always-on context and on static grounds (Decision). Evidence: the assessment (2026-11-12), an independent verification (2026-11-13: 60 checks, 57 confirmed, 3 corrected, 0 refuted; its corrections are used), the measurement (2026-11-13) and a re-check of the raw runs after the series, whose figures win where they differ. The notes hold local paths and are not published; the raw runs and the answer key's files stay on the owner's machine.

## Need

Two jobs. Dependency risk: Dependabot (`uv` and `github-actions`, weekly) covers the 12 packages `uv.lock` locks besides the project, and meridian has 0 Dependabot alerts; GitHub's dependency graph lists no npm package. Of Socket's GitHub app only its public check results were read; its project report needs the owner's sign-in. Nothing here is shown to cover the six npm packages `deploy/wsl/setup.sh` pins (`@openai/codex`, `pnpm`, `@deepseek-ai/dsh`, `@deepseek-harness-tui/dsh-tui`, `@deepseek-ai/dsh-hooks-claude-code`, `@deepseek-ai/dsh-hook-protocol`). Overlap: supply-chain-risk-auditor's advisory sweep of the `uv.lock` set does what Dependabot does for that set; it cannot read `setup.sh`. Property tests: `uv.lock` has no property-testing library; no tool here writes property tests.

Published evidence: supply-chain-risk-auditor about 92% against 60% of assertions on three fixtures, one run each (PR #227); property-based-testing's ablation, 3 runs per arm, Δ0.00 and Δ+0.50, which its README says does not establish better property tests (PR #235). ## What it installs, writes and sends

- Each plugin is one skill: no hooks, commands, agents, MCP or LSP servers (`claude plugin details`); `claude plugin validate --strict` exit 0 for both; all fetched files byte-identical to the pinned blobs.
- property-based-testing: SKILL.md with `effort: low` and five references; no script, no network. A skill's effort holds for the rest of the turn that invokes it (code.claude.com/docs/en/skills, read 2026-11-13), so it would lower the lead's high effort; its Python path needs Hypothesis, a new dev dependency.
- supply-chain-risk-auditor: SKILL.md with `allowed-tools: Read Write Bash Glob Grep` and two standard-library scripts the model runs with `uv run`. The collector sends package names and versions to `api.osv.dev`, the npm, PyPI and Go registries, `api.deps.dev`, `api.scorecard.dev` and `api.github.com`, no telemetry; it sends the token `gh auth token` prints to `api.github.com` (in the distro `gh` was not signed in during the series, so GitHub allowed 60 requests an hour). It reads manifests and lockfiles, not shell scripts, and takes npm metadata from the `latest` dist-tag, which named another version for 4 of the 6 pins on 2026-11-13. It writes an HTTP cache (about 35.4 MB per run) in the system temp folder, two uv script environments, `scripts/__pycache__` in the plugin's folder, and its report wherever the model puts it.

## Method

- Measured on Claude Code 2.1.322 with `claude-opus-5-5`; the stack's lead model `claude-fable-5-2` was not measured. The shared [method](data/ab-claude-code.md) and task R5 of the [task list](data/ab-tasks.md), with the [arm key](data/0003-key.txt). Both arms: one binary, `--effort high`, bypass permissions, a fresh memory folder, `DISABLE_AUTOUPDATER=1`, the method's deny rules on the command line, `TMPDIR`, `UV_CACHE_DIR` and `npm_config_cache` in a fresh folder per run, network open (R5 cannot run offline). The with arm adds `--plugin-dir` on a fresh copy of the plugin from a `git archive` of the pin. The runs used the owner's sign-in and wrote worktree entries under the main checkout's `.git/worktrees`; a session-only plugin load left a `pluginUsage` entry in `~/.claude.json`.
- R5, verbatim (sha256 `e901457da407d355dfab889d7aa0ce16a5863cc6d63f8a7c6878e1b24a5374e5`), in a detached worktree at `main` `9c5daaa` per run, order a1 b1 b2 a2 a3 b3, 02:02 to 02:26 ET.
- Fixed before the runs: [0003-prereg.txt](data/0003-prereg.txt) (sha256 `9454d46e3444e98de7047f39193b0887c2557aa018a4ba9adb47be0933320acb`; the published copy writes the home path as `~` and adds two bracketed notes), file time 02:01:15 ET; the first R5 run started at 02:01:42 ET, and the always-on runs before it. These times come from the owner's machine and cannot be proved from the repository; its first line says "~02:05", which is wrong. Grade: a run passes when it names all 18 packages (the 12 in `uv.lock` and the 6 npm pins), reports at least one true finding that Socket's check results and Dependabot lack, makes no finding the answer key contradicts and leaves the worktree unchanged; a with-run that breaks containment through the addition fails. The answer key came from OSV, PyPI and the npm registry ([script](data/0003_answer_key.sh), run at 01:56 ET); the grader was the measuring agent, not blind to the key. Rule for supply-chain-risk-auditor: adopt only if its arm passes at least 2 of 3 and the other at most 1, or both pass at least 2 of 3 and its arm uses at least 25% fewer median tokens; and its always-on delta at most 200 Claude tokens. Written after the first run: the 18-name check [script](data/0003_coverage.sh) (02:03:36 ET, before any run had replied), which is more lenient than the pre-registered wording for five names; read literally, no outcome changes.
- Before every run a guard checked that nothing listened on the paper Gateway's port and that no Gateway process ran; this series' guard matched command lines, and its own `claude` command lines carried the deny rule `Bash(*ibgateway*)`. The published [guard](data/0003_gateway_guard.sh) reads listeners, process names and executables instead. Records of what ran, with home paths replaced: the [shared functions](data/0003_common.sh), [always-on run](data/0003_ao_run.sh), [R5 run](data/0003_r5_run.sh) and [series](data/0003_r5_series.sh) scripts, and the [results](data/0003-results.json), assembled by hand from the raw runs. They add worktrees of the main checkout, so they are no re-run recipe.

## Decision

Not adopted, both plugins. supply-chain-risk-auditor: its arm passed 0 of 3 against 0 of 3, so neither branch of the rule holds and the 32.1% token saving does not count; its always-on delta (+142) was within the limit. In 3 of 3 with-runs it left its output in `/tmp`, and it cannot read the npm set that is the open part of the job. property-based-testing: no with/without task was run for it; its always-on delta, +316, is over the 200-token limit set for these plugins, it lowers the effort to low for the rest of the turn that invokes it, it needs a new dev dependency, and its published ablation does not show better tests.
