# ADR 0021: the IB Gateway's paper login without a person, with IBC
**Status: not adopted, 2026-11-14.** The upstream is retired and its repository archived; the lead approved this outcome under the brief of 2026-11-14 ("report that instead of forcing it"). Source lines for every point below: [the record](data/0021-record.md).

**Need:** after a machine restart nobody is logged in to the IB Gateway, port 4002 is closed, and the IBKR lane cannot follow the Alpaca lane into unattended running. Only the paper session matters here; no lane, no order.
**Candidate:** [IbcAlpha/IBC](https://github.com/IbcAlpha/IBC) **3.24.2** (2026-08-21; `IBCLinux-3.24.2.zip`, sha256 `cc097ca1…80c5`), GPL-3.0, Richard L King. Read 2026-11-14: archived, last push 2026-09-01, README headed "PROJECT RETIREMENT": "no further development of IBC… Nor will IBC be actively supported" ([Discussion 347](https://github.com/IbcAlpha/IBC/discussions/347)).
**Successors, read the same day:** no fork with standing. [gnzsnz/ib-gateway-docker](https://github.com/gnzsnz/ib-gateway-docker) (maintained, MIT) and NautilusTrader's `DockerizedIBGateway`, which drives that image, still bundle IBC 3.24.2, and need Docker, which this machine lacks. [ibg-controller](https://github.com/code-hustler-ft3d/ibg-controller) (MIT, created 2026-04-12, 48 stars) is Docker-only.
**Advisories:** the repository is archived, so no new report can be filed there. The retirement notice sends bug reports to the groups.io list.

## The six points, from IBC's 3.24.2 sources
1. **Display.** IBC starts the Gateway's Java window on `$DISPLAY` (user guide, crontab: `export DISPLAY=:10`). A unit can own a virtual display: `Xvfb` from Ubuntu's `xvfb` package (candidate 2:21.1.22-1ubuntu1.3, not installed). WSLg's `/tmp/.X11-unix/X0` exists only while a Windows user session runs WSL, so it is not clean after a restart; Xvfb is.
2. **Credentials.** `ibcstart.sh` passes `--user`/`--pw` straight into `java`'s argv. `/proc` here has no `hidepid`, so any user could read them, and the user guide calls this "strongly deprecated". `IbLoginId`/`IbPassword` in the `.ini` stay off the process list. IBC's log masks both (`DefaultSettings.getSettingSanitisedValue`). So a login rendered from `LoadCredentialEncrypted=` into the unit's `RuntimeDirectory` would have worked. This did not decide the ADR.
3. **Paper only.** `config.ini`: with `TradingMode=paper` "either the live or the paper-trading credentials may be supplied". The mode defaults to live when it is absent from both the argv and the `.ini` (`DefaultTradingModeManager`). A start check can fix the mode but cannot tell which login was typed. Only after login can `meridian/boundary.py` (jts.ini `tradingMode=p`, a paper-form account) tell. No IBKR page read today states whether a paper user's login needs a second factor.
4. **API port.** IBC can set the port (`OverrideTwsApiPort`) and `ReadOnlyApi`, and reject unknown clients (`AcceptIncomingConnectionAction=reject`). `TrustedTwsApiClientIPs` applies "only when FIX=yes". "Allow connections from localhost only" has no IBC setting and stays the owner's, in the Gateway's window. The Gateway binds `*:4002` (boundary.py).
5. **Session life.** IBKR: auto-restart "will require manual authentication once a week… each Sunday at 1:00 am ET"; IBC's `ColdRestartTime` re-logs in after that. `ExistingSessionDetectedAction=secondary` makes IBC cancel every existing-session dialog, so the owner's own manual login always wins.
6. **Account.** `boundary.py` reads `~/Jts` and `/proc` as the caller, and IBC uses `-DjtsConfigDir` (default `~/Jts`). The Gateway and the lane would run as one user, the owner, which is a user unit with linger, not `paper`. IBC also renames the Gateway's `ibgateway` launcher to `ibgateway1`, which breaks the owner's manual start (docs/LANES.md) and `setup.sh gateway`'s check.

## Decision
Not adopted. AGENTS.md admits only a cited, maintained upstream, and IBC is retired. Point 3 adds a second reason: "paper only by construction" would rest on which login the owner typed, and no start check can verify that.

**What the owner still does without it:** log in to Paper Trading in the Gateway's window after every machine restart. With the Gateway's own daily auto-restart (Configure › Lock and Exit), also after IBKR's weekly invalidation, Sunday 01:00 ET. If restarts happen only at the weekend, that is one typed login a week. Details: [record](data/0021-record.md#what-a-person-still-does).
**The alternative, for the owner to overrule knowingly:** the frozen 3.24.2 design ([record](data/0021-record.md#the-frozen-3242-design)): Xvfb, an owner user unit with linger, the login rendered into `RuntimeDirectory`. Its first drawback is point 3.
**Not a substitute:** IBKR's Web API (REST, OAuth 2.0) is a different API from the TWS socket API that NautilusTrader's adapter speaks.
**Revisit (by 2027-02-12, or earlier on any of these):** a maintained successor with standing; IBKR shipping an unattended login for the TWS API; the owner choosing the frozen release.

**Install and removal:** none. Nothing is installed, no unit is written, and there is no `UPSTREAM.md` row.
